# 热启动滤波器（Warm-start the filter）
> 译自 GMAT R2026a 帮助文档 ch15s07.html

我们已经了解了搭建、运行和质量检查 GMAT 滤波/平滑 OD 运行的全部内容。滤波器运行还有一个方面值得我们花点时间理解和探索。回想（或回头查看）我们生成的滤波器位置协方差图。该图有一个很大的初始协方差，然后需要一段时间——本例中可能 6 到 12 小时——才能达到稳定或"收敛"状态。这是因为我们执行了所谓的滤波器"初始化"或"冷启动"（cold start）。我们从自己对航天器状态和不确定度的粗略初始猜测启动滤波器。随着滤波器前向运行，它通过处理测量数据改进状态估计和不确定度。在滤波运行结束时，我们得到的状态估计和不确定度比起始时好得多。

在任务运行中，我们需要定期（可能每天）运行滤波器，下次启动滤波器时，最好从滤波器自己的结束状态估计和不确定度启动。我们可能认为可以手动实现：用滤波器对航天器状态的估计和完整（6x6，不只是对角元素）航天器轨道误差协方差矩阵更新脚本。我们还需要更新航天器 Cd 和 Cd 不确定度。这个过程很繁琐，甚至无法完整捕获滤波器的结束状态，因为没有办法手动向 GMAT 提供把 Cd 与航天器位置和速度联系起来的协方差分量。

好消息是，有一种简单得多的方法可以从先前估计的状态启动滤波器。在介绍滤波器生成的输出文件时，有一个文件我们没有描述——在滤波器 OutputWarmStartFile（输出热启动文件）参数上指定的 filter.csv 文件。

1. 转到你的 *<GMAT 安装目录>*/output 目录。找到 filter.csv 并在文本编辑器中打开阅读。

filter.csv 文件是逗号分隔文件，包含处理跨度内每个测量和时间更新处的完整滤波器状态与协方差记录。在文件中向右滚动查看表头行（如果你愿意，可以在 Excel 中打开文件以方便查看）。你应看到文件中每条记录包含滤波器的完整状态（即航天器位置和速度分量估计以及 Cd 估计）以及与该记录的状态和 Cd 估计关联的完整（7x7）协方差矩阵。此文件中的任何记录都包含滤波器启动并从该记录历元继续前向处理所需的全部信息。以这种方式从先前估计的状态和完整协方差矩阵启动滤波器称为"热启动"（warm start），filter.csv 文件称为热启动文件。

> **注意**：热启动文件中存储的协方差实际上是完整协方差矩阵的平方根。协方差列的表头表明了这一点（SqrtCovariance）。完整协方差矩阵 P 可由平方根协方差按公式 P = SqrtCovariance × SqrtCovariance^T 恢复。

让我们快速演示如何执行热启动。

2. 按下面所示更新任务序列中的滤波器 ExtendedKalmanFilter 配置。直接把当前滤波器实例注释掉或删除，然后粘贴这段新代码可能更方便。

```
%
%   Estimator
%

Create ExtendedKalmanFilter EKF;

EKF.ShowProgress         = True;
EKF.Measurements         = {EstData};
EKF.Propagator           = Prop;
EKF.ShowAllResiduals     = On;
EKF.InputWarmStartFile   = 'filter.csv';
EKF.WarmStartEpochFormat = 'UTCGregorian';
EKF.WarmStartEpoch       = '10 Jun 2014 18:00:00.000';
EKF.ReportFile           = 'filter.txt';
EKF.MatlabFile           = 'filter.mat';
```

上述脚本中，滤波器改为从输入热启动文件 filter.csv 读取（InputWarmStartFile），并指定热启动历元 WarmStartEpoch 为 2014-06-10 18:00（UTCGregorian 格式）。

3. 在脚本窗口底部，点击 "Save,Sync" 按钮。

这里，我们把手头的 filter.csv 热启动文件指定为 InputWarmStartFile（输入热启动文件），意味着 GMAT 现在将从该文件读取而不是写入。我们还指定了 WarmStartEpoch（热启动历元，及历元格式）。这告诉 GMAT 使用输入热启动文件中的哪条记录作为 GMAT 的起点。在本例中，我们选择不写出新的滤波器 OutputWarmStartFile，但我们也可以同时这样做，只要选择与输入热启动文件不同的文件名。让我们运行滤波器，看看热启动如何工作。

4. 点击 "Save,Sync,Run" 按钮、点击工具栏中的蓝色 "Run" 箭头，或按 F5 键运行脚本。
5. 运行完成后，转到你的 *<GMAT 安装目录>*/output 目录。找到 filter.txt 并在文本编辑器中打开阅读。

查看滤波器输出报告文件顶部的航天器初始条件。你现在应看到初始航天器历元状态在我们指定的热启动历元处。如果你愿意，可以手动把滤波器输出报告中报告的初始状态与 filter.csv 热启动文件中的 10 Jun 2020 18:00（原文如此，应为 2014）记录比较——它们应匹配。最重要的是，输出文件中报告的 7x7 初始协方差也将与热启动文件记录的 7x7 协方差匹配（如果你把热启动文件中的平方根协方差转换为完整协方差）。

接下来，在输出中向下滚动到滤波器测量残差报告。注意残差报告从 10 Jun 2014 18:10 的测量开始。热启动滤波器时，它会自动忽略所选热启动历元之前的任何测量，并从热启动历元之后的第一个测量开始前向处理。这是因为该历元处的热启动记录已包含了处理所有更早测量数据的效果。（顺便说一句，由于前向滤波器忽略了 18:00 之前的测量，反向滤波器和平滑器也将忽略更早的测量数据，因为它们对要处理哪些测量的认知完全来自前向滤波运行。）

如果你在输出文件中进一步向下滚动到 FILTER STATE INFORMATION（滤波状态信息）报告，你会看到本次运行的结束时间和最终估计状态与原始全跨度运行得到的一致。热启动的目的是让滤波器从热启动历元继续运行，就像它从未停止过一样。选择任何热启动历元都会在运行结束时得到完全相同的估计状态和协方差。

在本例中，我们得到相同的结束状态，因为我们只是在重新处理与冷启动运行相同的数据集，唯一区别是选择了不同的起点。在正常任务运行中，热启动记录用于在每次运行滤波器时用新获得的数据把滤波器估计状态持续向前推进。常规 OD 场景的此过程概要如下图所示：

如流程图所示，理想情况下滤波器只冷启动（初始化）一次，然后以热启动模式连续运行，每天的新运行从前一次运行的输出热启动文件中选择的历元开始（通常是最后或最近的热启动记录）。实际中，偶尔需要重新初始化滤波器。如果发生无法在滤波器中建模的严重航天器推力事件，或者（更常见地）由于增加新跟踪站或现有跟踪站发生重大变化导致滤波场景改变，就可能需要这样做。
