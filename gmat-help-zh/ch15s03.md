# 估计轨道（Estimate the orbit）
> 译自 GMAT R2026a 帮助文档 ch15s03.html

在本节中，我们将逐步创建使用扩展卡尔曼滤波（EKF）估计轨道的脚本。此任务所需的许多资源与我们在仿真练习中使用的相同。但有几个新资源需要处理，我们会在遇到时介绍。

首先，为估计任务新建一个空白脚本文件。你可以在不关闭仿真脚本的情况下执行此操作——GMAT 可以同时加载多个脚本，但从现在起我们将忽略仿真脚本。

1. 在 GMAT 的 File 菜单中，选择 New > Script（新建 > 脚本）。

与之前一样，GMAT 图形界面中将打开一个新脚本窗口。

2. 在 GMAT 脚本窗口中输入或粘贴以下内容。

```
Create Spacecraft EstSat;

EstSat.DateFormat        = UTCGregorian;
EstSat.Epoch             = '10 Jun 2014 00:00:00.000';
EstSat.CoordinateSystem  = EarthMJ2000Eq;
EstSat.DisplayStateType  = Cartesian;
EstSat.X                 =  576.8
EstSat.Y                 = -5701.1
EstSat.Z                 = -4170.5
EstSat.VX                = -1.7645
EstSat.VY                =  4.1813
EstSat.VZ                = -5.9658
EstSat.DryMass           = 10;
EstSat.Cd                = 2.0;
EstSat.CdSigma           = 0.1;
EstSat.Cr                = 1.8;
EstSat.DragArea          = 10;
EstSat.SRPArea           = 10;
EstSat.Id                = 'LEOSat';
EstSat.SolveFors         = {CartesianState};

%
%   Mission sequence
%

BeginMissionSequence
```

上述脚本创建估计用航天器 EstSat：初始状态精度较低（引入约 100 m 位置误差），Cd 改为 2.0 并新增 CdSigma（Cd 不确定度 0.1），SolveFors 指定估计笛卡尔状态。

3. 在脚本窗口底部，点击 "Save,Sync,Run" 按钮。
4. GMAT 会询问你是否要保存脚本并将其设为活动脚本。点击 "Yes" 并选择目录保存脚本。把它保存到与仿真脚本相同的位置，命名为 "filter.script"。
   a. 保存后，GMAT 控制台窗口应显示消息 "Successfully interpreted the script."（脚本解释成功）。

与仿真练习一样，我们从航天器对象开始。在仿真用例中，它代表我们希望仿真的轨道的航天器初始条件。在本例中，我们的航天器对象配置了估计的初始条件。为避免"作弊"——即给估计过程过于精确的状态初始估计——我们降低了初始状态的精度，有效引入约 100 米位置误差和几 cm/s 速度误差，这对跟踪良好的 LEO 卫星很典型。

我们还添加了一个新参数——SolveFors（求解参数）。它列出一个或多个我们希望在滤波运行中估计的航天器参数。这里我们使用 GMAT 内置的 solve-for 关键字之一，指定我们打算估计航天器笛卡尔状态，即 J2000 地心坐标系中航天器的位置和速度（X, Y, Z, VX, VY, VZ）。在本教程后面，我们将把阻力系数估计添加到此列表。

你可能还注意到，我们把航天器 Cd（阻力系数）值从仿真器中的 2.2 改为这里的 2.0 用于估计。这是因为除了航天器位置和速度外，我们还将尝试估计阻力系数。因为要估计 Cd，我们还添加了新参数 CdSigma，用于设置我们对阻力系数初始估计的假定不确定度。虽然在本例中我们知道猜测的误差有多大，但实际中你当然不知道，可能需要一些试验。

接下来添加对 GPS 测量建模所需的航天器硬件。

5. 在 GMAT 脚本窗口中输入或粘贴以下内容。

```
%
%   Spacecraft hardware
%

Create Antenna GpsAntenna;
Create Receiver GpsReceiver;

GpsReceiver.PrimaryAntenna = GpsAntenna;
GpsReceiver.Id             = 800;
GpsReceiver.ErrorModels    = {PosVecModel}

Create ErrorModel PosVecModel;
 
PosVecModel.Type       = 'GPS_PosVec'
PosVecModel.NoiseSigma = 0.010;
```

上述脚本与仿真练习相同：创建天线、接收机（Id 800）和 GPS_PosVec 误差模型（噪声 sigma 0.010 km）。

6. 在脚本中，回到航天器参数配置部分，在航天器参数列表底部添加以下内容。

```
EstSat.AddHardware       = {GpsReceiver, GpsAntenna};
```

7. 在脚本窗口底部，点击 "Save,Sync" 按钮。

这里我们只是复用仿真所用的相同硬件配置。然而，在本例中，误差模型上指定的 NoiseSigma 现在是现有数据中假定的测量噪声。我们使用与仿真中设置的相同值，略有"作弊"。实际中，你不会这么清楚地知道测量噪声，可能需要试验，或对轨道确定残差进行分析，以找到合适的值。

接下来，快速创建跟踪文件集、力模型和传播器。

8. 在 GMAT 脚本窗口中输入或粘贴以下内容。

```
%
%   Tracking file sets
%

Create TrackingFileSet EstData;

EstData.FileName = {'gps_posvec.gmd'};

%
%   Force model
%

Create ForceModel FM;

FM.CentralBody                       = Earth;
FM.PrimaryBodies                     = {Earth};
FM.GravityField.Earth.Degree         = 8;
FM.GravityField.Earth.Order          = 8;
FM.GravityField.Earth.PotentialFile  = 'JGM2.cof';
FM.SRP                               = On;
FM.Drag.AtmosphereModel              = 'JacchiaRoberts';
FM.Drag.CSSISpaceWeatherFile         = 'SpaceWeather-All-v1.2.txt'
FM.Drag.HistoricWeatherSource        = 'CSSISpaceWeatherFile';
FM.ErrorControl                      = None;

%
%   Propagator
%

Create Propagator Prop;

Prop.FM              = FM;
Prop.Type            = 'RungeKutta89';
Prop.InitialStepSize = 60;
Prop.MinStep         = 0;
Prop.MaxStep         = 60;
```

上述脚本创建跟踪文件集 EstData（指向仿真生成的 gps_posvec.gmd）、与仿真相同的力模型 FM 和传播器 Prop（RungeKutta89，定步长 60 s）。

9. 在脚本窗口底部，点击 "Save,Sync" 按钮。

力模型和传播器与我们在仿真脚本中使用的相同。对于跟踪文件集，我们把实例名改为更合适的 "EstData"。所指定的跟踪数据文件现在是估计过程中要读取的输入文件，因此它指向我们在仿真运行中创建的文件。注意我们去掉了 AddTrackingConfig 赋值。当你把跟踪文件集用于估计时，GMAT 会检查输入跟踪数据文件中的数据并自动确定跟踪测量路径。用户无需为估计过程指定这些。接下来创建卡尔曼滤波估计器对象。

10. 在 GMAT 脚本窗口中输入或粘贴以下内容。

```
%
%   Estimator
%

Create ExtendedKalmanFilter EKF;

EKF.ShowProgress         = True;
EKF.Measurements         = {EstData};
EKF.Propagator           = Prop;
EKF.ShowAllResiduals     = On;
EKF.OutputWarmStartFile  = 'filter.csv';
EKF.ReportFile           = 'filter.txt';
EKF.MatlabFile           = 'filter.mat';
```

上述脚本创建扩展卡尔曼滤波器 EKF：显示进度，测量数据为 EstData，使用传播器 Prop，显示全部残差，输出热启动文件 filter.csv、报告文件 filter.txt 和 MATLAB 文件 filter.mat。

11. 在脚本窗口底部，点击 "Save,Sync" 按钮。

与仿真器一样，估计器也被指定了跟踪文件集。在本例中，跟踪文件集包含估计器的输入数据。每条输入测量记录上的接收机 ID 把输入数据链接到我们配置的 GPS 接收机、航天器和误差模型资源。我们还为估计器指定了一个传播器（及其挂载的力模型），用于在估计过程中传播航天器轨道。

ShowProgress 设置使 GMAT 在估计运行时在控制台窗口中提供详细输出，ShowAllResiduals 将告诉 GMAT 在估计运行时显示残差图。EKF 的 ReportFile 是滤波器将生成的详细报告，帮助我们解读和质量检查（QA）运行结果。MatlabFile 是将从运行生成的 MATLAB 格式文件。它包含滤波器运行时生成的有用数据，我们稍后将用它辅助质量检查运行。注意，只有运行 GMAT 的机器上安装了 MATLAB，且 GMAT 正确配置为使用 MATLAB 连接，才能生成 MatlabFile。配置 MATLAB 接口的详情见"MATLAB Interface（MATLAB 接口）"。

OutputWarmStartFile 是一个额外的输出文件，可用作后续运行的输入，使滤波器以"连续估计"模式工作。我们将在本练习后面回顾此文件，了解其工作方式。

与仿真器不同，滤波器没有开始或停止时间参数。滤波器将从航天器对象的初始历元开始，处理输入跟踪数据文件中存在的所有测量。

GMAT 轨道确定滤波器的工作方式是：持续传播状态估计的不确定度，并在每个测量处将状态不确定度和测量噪声与测量残差比较，以决定新测量应被拒绝还是接受；若接受，该测量应以多大强度用于修正当前状态估计。状态不确定度的传播从状态不确定度的初始估计开始，并考虑力建模和传播误差的假定模型。当我们在没有测量的情况下传播状态时，状态不确定度因力建模误差而增长。当我们纳入（接受）一个测量时，状态不确定度减小，因为测量改善了我们的轨道认知。稍后运行滤波器时我们将看到这些效应的实际表现，但首先需要创建和配置对状态及力模型不确定度建模所需的对象。

12. 在 GMAT 脚本窗口中输入或粘贴以下内容。如果你愿意，可以把 EstSat.ProcessNoiseModel 赋值移到其他航天器初始参数设置处，使它们归在一起。

```
%
%   Process noise model
%

Create ProcessNoiseModel SNC;

SNC.Type             = 'StateNoiseCompensation';
SNC.CoordinateSystem = EarthMJ2000Eq;
SNC.AccelNoiseSigma  = [1.0e-9 1.0e-9 1.0e-9];
SNC.UpdateTimeStep   = 120.

EstSat.ProcessNoiseModel = SNC;
```

上述脚本创建过程噪声模型 SNC（类型 StateNoiseCompensation，状态噪声补偿），坐标系 EarthMJ2000Eq，加速度噪声 sigma 三个分量均为 1.0e-9，更新时间步长 120 s，并挂接到 EstSat。

13. 在脚本窗口底部，点击 "Save,Sync" 按钮。

这里我们创建了一个名为 Process Noise Model（过程噪声模型）的新资源的实例。该资源对没有测量时航天器传播的误差建模。这是预测"过程"中的误差。它试图对诸如重力、SRP 和阻力建模不精确导致的误差，以及我们配置的力模型中未显式建模的任何已知或未知小力导致的误差进行建模。你可以看到，该模型在指定坐标系（这里是地球 J2000 坐标架）中为计算出的标称加速度指定一组三个噪声值。此模型被指定给航天器，因为它与该航天器的轨道和力模型相关联。该模型提供的过程噪声将按过程噪声模型 UpdateTimeStep 定义的间隔添加到状态不确定度中，我们设为每 120 秒。在实际运行中选择合适的过程噪声值通常需要试验和分析。

GMAT 实现的过程噪声方法称为 State Noise Compensation（状态噪声补偿），如有兴趣可在参考文献 1 中阅读更多内容。现在深入此模型的细节会离题太远。

接下来，我们将把阻力系数估计添加到滤波运行中。对低地球轨道航天器而言，估计阻力系数或某种阻力修正因子是常见做法。这是因为阻力是该轨道上影响航天器的各种力中建模最差的一种。解析大气密度模型仅因大气化学的庞大和复杂就有高达 30% 甚至更多的固有误差。除此之外，阻力不仅取决于假定的阻力系数（Cd），还取决于航天器面积（通常只有粗略建模且通常是动态的）和航天器质量（可能不精确已知）。估计阻力修正值能以聚合方式补偿所有这些误差，可显著改善轨道估计和预报的精度。

14. 在 GMAT 脚本窗口中输入或粘贴以下内容。

```
%
%   Create the drag solve-for
%

Create EstimatedParameter FogmCd

FogmCd.Model            = 'FirstOrderGaussMarkov';
FogmCd.SolveFor         = 'Cd';
FogmCd.SteadyStateValue = 2.0;
FogmCd.SteadyStateSigma = 0.05;
FogmCd.HalfLife         = 864000;
```

上述脚本创建估计参数 FogmCd：模型为一阶高斯-马尔可夫（FirstOrderGaussMarkov），求解量为 Cd，稳态值 2.0，稳态 sigma 0.05，半衰期 864000 s。

15. 在脚本窗口底部，点击 "Save,Sync" 按钮。

这是另一个新资源——EstimatedParameter（估计参数）资源。我们前面提到，GMAT 有一组内置 solve-for 参数，包括阻力系数 solve-for 参数。然而，内置 Cd solve-for 不适合与滤波器一起使用，因为它不包含过程噪声建模。EstimatedParameter 资源允许用户为某些 solve-for 配置更复杂的建模，方式更适合滤波器并包含过程噪声建模。此资源把 Cd 估计实现为"一阶高斯-马尔可夫"（FOGM）过程。可在参考文献 2 中阅读更多关于此模型的内容。这类模型包含三个基本参数——稳态值、稳态不确定度（sigma）和"衰减"半衰期。

滤波器运行时，所有估计参数的不确定度在没有测量的情况下传播时总是增大，处理测量时总是减小。FOGM 变量的稳态值是在没有测量时参数将自动回归到的值。一般应始终设为对实际值的最佳猜测（同样，这里我们假装不知道实际值）。类似地，FOGM 变量的稳态不确定度是在没有测量时参数不确定度将自动回归到的值。FOGM Cd 不确定度不会持续无上限增长，而是在经过一定时间后，在 SteadyStateSigma 值处趋于最大值。稳态值和 sigma 趋于平稳所需的时间（以秒计）由 HalfLife 参数给出，它指定当前 Cd 估计回归到 SteadyStateValue 所设极限值一半所需的时间。

我们需要把该估计参数添加到航天器的 solve-fors 列表。

16. 找到设置 EstSat.SolveFors 参数的行，按下面所示编辑以添加 FOGM Cd 估计。

```
EstSat.SolveFors         = {CartesianState, FogmCd};
```

17. 在脚本窗口底部，点击 "Save,Sync" 按钮。

在 GMAT 中，参数或资源实例（如 FogmCd）在创建之前被赋值没关系。不必把创建 FogmCd 估计参数的代码放在 GMAT 脚本中 EstSat.SolveFors 赋值之前。GMAT 会在运行时尝试把所有内容正确连接起来。只要所有必需的对象在脚本中某处定义，一切就应正常工作。

最后要做的是在任务序列中添加执行滤波运行的代码。

18. 按下面所示更新任务序列，然后点击 "Save,Sync"。

```
%
%   Mission sequence
%

BeginMissionSequence

EstSat.OrbitErrorCovariance = diag([1e-2 1e-2 1e-2 4e-10 4e-10 4e-10]);

RunEstimator EKF;
```

你可能预料到会看到 RunEstimator 命令。与 RunSimulator 一样，RunEstimator 命令有一个参数——要执行的滤波器实例名称。该命令指示 GMAT 处理输入跟踪数据测量，并使用挂载到滤波器及其关联对象的传播器、航天器、误差模型和过程噪声模型执行估计。

我们在任务序列中还有一条额外命令。在运行估计器之前，我们使用 **diag()** 命令设置航天器初始轨道不确定度。滤波器运行时会持续传播和调整航天器不确定度（"协方差"），但它需要某个不确定度起始值。航天器位置和速度不确定度由一个 6x6 矩阵表示（三个位置分量和三个速度分量），但初始化时我们只关心矩阵的对角分量。diag() 函数是创建对角矩阵的便捷方法。这里我们指定 EstSat 初始状态的三个位置（1e-2 km^2）和速度（4e-10 km^2/sec^2）分量的初始"协方差"。

你可能想知道这些值从何而来。我们在某种程度上又稍微"作弊"了。由于我们知道仿真中使用的航天器状态，我们也知道本次运行中 EstSat 的误差。回想上面说过，我们降低了估计脚本初始状态的精度，从而引入约 100 米位置误差和几 cm/s 速度误差。我们在这里沿 EstSat.OrbitErrorCovariance 对角线指定的值就是这些误差的平方（协方差单位是平方不确定度），单位为 km^2 和 km^2/sec^2。在实际运行中，你不会这么清楚地知道初始不确定度，通常必须通过经验、研究或分析，对初始轨道不确定度做出有根据的"数量级"猜测。

19. 点击 "Save,Sync,Run" 按钮、点击工具栏中的蓝色 "Run" 箭头，或按 F5 键运行脚本。

脚本应在几秒内完成。与运行仿真器时不同，这次你会在图形界面和控制台窗口中看到大量动态。首先，图形界面中会出现类似下图的窗口。这是所有测量残差的图。

> [图：全部测量残差图]

纵轴是以千米为单位的测量残差，横轴是以原子时（TAI）修正儒略日（MJD）表示的测量时间。注意残差的散布与我们在仿真中施加的测量噪声（10 米）一致。

如果你在控制台窗口中向后滚动，会找到初始状态与估计参数的摘要，以及最终状态与估计参数（处理完所有测量后），还有最终协方差矩阵。这是有用的信息，但不足以全面质量检查运行结果，因此现在让我们深入研究运行生成的其他输出文件。
