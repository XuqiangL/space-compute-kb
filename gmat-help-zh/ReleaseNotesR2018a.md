# GMAT R2018a 发行说明（ReleaseNotesR2018a）

> 译自 GMAT R2026a 帮助文档 ReleaseNotesR2018a.html

GMAT R2018a 于 2018 年 3 月发布。这是自 2017 年 6 月以来的第一个公开版本，是本项目的第 12 个版本。以下为本版本关键变更摘要；完整清单见 JIRA 上的完整 R2018a 发行说明。

## 里程碑与成就

GMAT 近期在业务任务支持中获得显著采用：

- GMAT 现在被用作太阳动力学天文台（SDO）机动规划和产品生成的主要系统。
- GMAT 现在被用作太阳和日球层天文台（SOHO）任务轨道确定的主要业务工具。
- GMAT 现在被用作先进成分探测器（ACE）任务机动规划、轨道确定和产品生成的主要业务工具。
- GMAT 现在被用作 Wind 任务机动规划、轨道确定和产品生成的主要业务工具。
- 2018 年 4 月，凌日系外行星巡天卫星（TESS）任务计划发射。TESS 从提案开发到业务运行一直使用 GMAT 作为任务设计和机动规划的主要工具。
- 2018 年 4 月，LRO 项目将举行业务就绪评审，对 GMAT 进行最终评估，以取代 GTDS 成为月球勘测轨道飞行器（LRO）的主要业务轨道确定（OD）工具。

## 新功能

### 轨道确定增强

GMAT 估计系统新增以下功能：

- 批估计器现在支持在用户指定的迭代次数后冻结用于估计的测量的能力。该功能避免了当某些测量接近 sigma 编辑边界、在一次迭代中被反复移除又在下一次迭代中被加回时，解附近可能出现的估计器抖动。
- 计算 Doppler 和 DSN_TCP 测量残差时的数值计算得到改进，改善了残差的噪声特性。
- GroundStation 对象支持新的对流层模型——Marini 模型，与 GTDS 中使用的实现一致。Marini 模型的一个业务优势是它不需要输入地面站的气象数据（接受气象数据的模型可能更精确）。
  - 时间现在使用三个数据成员建模：日数、日内秒数和秒的小数部分。高精度时间在地球自转、行星星历等适当模型中精确实现。
  - 距离差使用 Taylor 级数和差分 Chebyshev 多项式计算。
- 测量仿真现在在环绕地球以外天体时也考虑中心天体掩星。
- 估计现在支持带先验约束的开普勒状态估计。
- 对于 BLS 估计，用户可以选择使用残差的加权均方根（WRMS）或预测加权均方根（WRMSP）进行测量编辑。现在会报告仰角编辑数据的残差。
- 批估计器报告现在显示配置中使用的输入文件名称和观测时间跨度。此外还包括航天器硬件配置和新的测量统计信息。
- GMD 文件改进。

GMAT 的轨道确定（OD）能力已显著增强。与所有新版本一样，使用 GMAT OD 能力的任务在将新版本 GMAT OD 用于业务目的之前，应执行基线回归/性能测试。

示例脚本：

- 见 `Ex_CompareEphemeris.script`：在非地球天体进行星历比较的新示例。
- 见 `Ex_MergeEphemeris.script`：演示星历合并的示例。

### 内置优化器

GMAT 现在包含一个由 GMAT 团队开发的内置优化器 Yukon。该算法使用带有效集 QP 子问题算法的 SQP 线搜索算法。Yukon 设计用于小规模问题，不适用于大型稀疏优化问题。更多信息见 Yukon 参考文档。

## 改进

- 潮汐建模得到改进，GMAT 现在支持月球潮汐。
- STM（状态转移矩阵）传播现在包括来自阻力模型的变分项。
- 谐波重力对 STM 贡献的次数和阶数现在可由用户设置，默认为重力文件上的最大阶数或 100（取较低者）。
- 决定 OrbitView 资源存储绘图点数的缓冲区大小现在向用户公开。
- IRI2007 电离层模型有显著的性能改进。
- 脚本编辑器高亮显示首次解析时发现的错误和警告。
- GMAT 现在支持 Code 500 星历的体固和 TOD 坐标系，并支持 Code 500 星历格式中的所有中心天体。
- GMAT 新增 CommandEcho 命令，支持在任务序列中执行命令时将其打印到消息窗口和日志文件。该命令在调试用户脚本时特别有用。更多信息见 CommandEcho 参考文档。
- Code500 传播器类型现在在读取 Code500 文件时自动检测字节序（endianness）。
- STK 星历传播器现在使用 Hermite 插值，并对包含少于 7 行数据的弧段在位置插值中包含速度信息：对少于 7 行数据的弧段，通过构造位置的 Hermite 插值多项式，然后对位置插值多项式求导获得速度。
- 现在可以在任务执行期间（即 BeginMissionSequence 命令之后）设置星历传播器的步长。
- 启动文件现在允许可选地更新用户配置文件。这避免了多个 GMAT 实例同时尝试写入用户配置文件时遇到的系统错误问题。
- Python 数据文件实用程序现在更新 IRI2007 模型使用的数据文件。
- GMAT 基于 CMake 的构建系统现在支持外部团队开发的插件组件。
- GMAT 现在支持 GUI 插件组件。

## 兼容性变更

- 批估计现在要求使用定步长积分。
- CelestialBody 资源上的 RotationDataSource 已弃用，不再有效。
- Spacecraft 的 EstimationStateType 参数已弃用。
- EphemerisFile 的 OutputFormat 选项 'UNIX' 和 'PC' 已弃用，应改用 'BigEndian' 和 'LittleEndian'。
- ForceModel 资源上的 EarthTideModel 已重命名为 TideModel。
- GMAT 现在通过命令行接口返回错误代码，以指示系统执行期间是否遇到问题。
- 使用 Write 命令将资源属性写入 ReportFile 时，仅写入标量实数；非实数或数组的属性将被忽略并发出警告。

## R2019a 中的即将变更

这是在 Windows 7 上测试的最后一个 GMAT 版本。

## 已修复与已知问题

### 已修复问题

本版本关闭了 112 多个 bug。关键 bug 及解决方案清单见 "Critical Issues Fixed in R2018a" 报告；次要问题见 "Minor Issues Fixed for R2018a" 报告。部分修复包括：

- STK 星历传播器现在正确处理少于 5 行数据的弧段。
- 包含事件边界的 STK 星历文件现在在 NumberOfEphemerisPoints 关键字值对中正确计算所表示的星历行数。
- 描述 CCSDS 星历文件中星历不连续来源的注释现在写在元数据块内。

### 已知问题

所有已知问题清单见 "All Known Issues for R2018a" 报告。本版本中几个重要的已知问题：

| ID | 描述 |
| --- | --- |
| GMT-5417 | 自适应步长控制在 GMAT 导航系统中使用时表现不一致。仿真和估计目前需要定步长积分。 |
| GMT-6202 | 某些情况下 DSN_TCP 和 Doppler 电离层校正中可能观察到高达 1 mm/sec 的尖峰。IRI2007 模型的电子密度随时间变化存在一些跳变，当起始和结束信号路径位于这些跳变的不同侧时会产生尖峰。 |
