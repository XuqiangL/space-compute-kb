# 审查并质量检查滤波运行（Review and quality check the filter run）
> 译自 GMAT R2026a 帮助文档 ch15s04.html

转到你的 *<GMAT 安装目录>*/output 目录。那里应有三个新文件——filter.txt、filter.mat 和 filter.csv。我们从 filter.txt 开始。

> **注意**：生成 MATLAB 数据文件需要 GMAT 正确连接到已授权的 MATLAB 实例。如果你没有 MATLAB，则无法生成 MATLAB 数据文件，应跳过下面的 Python 绘图练习。如果没有 MATLAB，仍可从运行生成适合绘图的数据文件。许多参数（如航天器 OrbitErrorCovariance、Cd、CdSigma 等）可以动态写入外部报告文件。具体做法详见 ReportFile 参考文档。

1. 在文本编辑器中打开 filter.txt 阅读。

filter.txt 文件是详细的估计器输出报告，是审查滤波运行状态的第一站。报告中有很多细节，我们这里只讲要点。从上到下，文件包含以下内容：

- 初始航天器状态与协方差，
- 航天器硬件摘要，
- 力建模选项摘要，
- 测量建模摘要，
- 相关空间环境常数摘要，
- 全部滤波测量残差报告，
- 滤波估计摘要报告，
- 滤波协方差报告。

FILTER MEASUREMENT RESIDUALS（滤波测量残差）报告之前的所有内容只是把你提供给滤波器的输入配置回显出来。你可以在排查故障时使用这些部分，或确认 GMAT 按你的意图解释了输入。

查看 FILTER MEASUREMENT RESIDUALS 报告。它显示滤波器处理每个测量的结果。每条输入 GPS_PosVec 跟踪数据测量记录在此报告中产生三行——第一行为 X 值，第二行为 Y 值，第三行为 Z 值。每行（从左到右）以测量记录号、测量时间（此处为 UTC）、测量类型名（GPS_PosVec）以及与测量关联的航天器名称开头。接下来是可能出现编辑标志（edit flag）的一列。由于本次运行使用仿真数据，你的运行中很可能没有编辑标志，但你可能会看到少量测量被标记为 SIG 编辑准则。此标志稍后会说明。

接下来行内出现测量观测值（Observed）。这是从输入跟踪数据文件中提取的测量精确值。下一列显示测量的计算值（Computed）。计算值是测量的预测值，通过用我们在脚本中配置的力建模选项传播航天器当前估计状态得到。如果估计进展顺利，计算值通常应接近观测值。最后一列显示观测值与计算值之差。这称为测量"残差"（residual），就是滤波器运行时图中绘制的值。最后一列 "Elev" 是测量仰角，GPS_PosVec 测量不填写此列。

滤波器用残差值决定接受还是拒绝测量。如果计算出的残差大于组合状态不确定度与测量噪声的三倍，滤波器将忽略该测量。若发生这种情况，该测量将在报告中以 SIG（表示"sigma"）编辑标志标识。这称为"缩放残差检查"（scaled residual check），倍乘值（本例中默认为 3）如有需要可在 EKF 资源实例上更改。由于本次运行使用仿真数据，你可能看不到任何被编辑的点，但使用真实数据时更可能遇到自动 sigma 编辑。对任何滤波运行做质量检查时，你都应审查此报告，确保从头到尾大部分数据被接受。如果在报告中某处开始看到过多数据被编辑，这表明滤波器出了问题。也许是过程噪声不足导致协方差变得过小，也许是假定的测量噪声太小，或者发生了未建模的机动。

输出报告的下一节 FILTER MEASUREMENT STATISTICS（滤波测量统计）是残差报告的有用摘要。这里你可以看到数据跨度的起止时间。你应确认它们符合预期。你还可以看到本次运行可用观测总数和被接受（"Used For Estimation"，用于估计）数量的摘要。若有点被编辑剔除，将在 "Sigma Editing" 计数中注明。在其下方，你可以一眼看到运行中接受了多少数据以及总体残差统计。运行良好的滤波器通常应接受几乎所有可用的良好跟踪数据。请记住，我们在这里看的是仿真跟踪数据，它比真实跟踪数据更接近完美——真实数据常有更多离群值和不良测量。你对任务数据接受率的预期需要通过数据分析和趋势来确定。

输出报告接下来是 FILTER STATE INFORMATION（滤波状态信息）。它给出运行结束时（具体即最后一个被处理测量的时刻）估计的航天器状态及任何其他估计参数的摘要。在本例中，我们看到估计的笛卡尔状态和 Cd 值，以及每个估计参数的最终不确定度。为方便起见，GMAT 还报告估计状态的开普勒根数，以及可从笛卡尔根数导出的一组其他有用轨道参数。GMAT 还在这里报告完整协方差矩阵（此处为 7x7，因包含 6 元素笛卡尔状态和 Cd），以及笛卡尔和开普勒根数集的相关系数矩阵。

最后，输出报告显示详细的 FILTER COVARIANCE REPORT（滤波协方差报告）。滤波协方差报告在所有测量时刻和过程噪声更新间隔处显示记录。回想一下，我们在过程噪声模型上把 UpdateTimeStep 设为 120 秒。在协方差报告中，测量之间每隔 120 秒会写入额外记录。每条记录显示速度-法向-副法向（VNB）坐标架中的当前轨道位置不确定度。你应能看到协方差从我们在 EstSat OrbitErrorCovariance 上指定的输入值 100 米开始，且轨道不确定度在使用测量时总是减小，在测量之间总是增大。

每条测量记录还包括计算出的缩放残差报告。这是一个无量纲值，在上述残差 sigma 编辑检查中计算。由于我们使用默认 sigma 编辑准则 3，任何缩放残差值大于 3 的测量都会被编辑剔除。如果你运行中有点被编辑，可通过在此报告节中查找其缩放残差来核实。注意，GPS_PosVec 每个分量（X、Y、Z）的缩放残差是分别计算的，但如果三元组中任何一个超过缩放残差阈值，三个分量都会被拒绝。

滤波输出报告——尤其是滤波测量统计节——对评估滤波运行的状态和质量非常有用，但图形往往是快速审查大量数据的更有用方式。接下来，让我们看一些用 filter.mat MATLAB 输出文件生成图形的工具。如果你有 MATLAB 但没有得到 filter.mat 文件，则 GMAT MATLAB 接口有问题。配置与故障排查信息见"MATLAB Interface（MATLAB 接口）"。

我们先绘制滤波残差比。你必须有包含 scipy、numpy、pandas 和 matplotlib 的 Python 3 安装才能运行这些示例。如果你使用 Anaconda Python，应该没问题。

2. 打开 DOS 提示符，导航到包含示例 Python 分析脚本的目录。它们位于 *<GMAT 安装目录>*/utilities/python/navigation 目录。
3. 在该目录中，输入以下命令：

```
python plot_residual_ratios.py <filter.mat 的完整路径>
```

几秒后，你应看到类似下图的图。它显示我们之前在报告文件滤波协方差报告节中看到的所有缩放残差值。以图的形式更容易评估总体趋势。±3 之间的绿色高亮区域显示我们使用的缩放残差阈值门限。绘制在此区域内的任何点代表被接受的测量。若有任何点出现在高亮区域之外，它们被缩放残差编辑准则拒绝了。

> [图：缩放残差比图]

真实跟踪数据不会这么好看，预期会显示比纯随机噪声更多的"结构"。审查缩放残差图时，你应确保大部分数据被接受，尤其要确保被接受数据的分布在整个运行（开始、中间和结束）中大致相似。顺便说一句，这些 Python 脚本还会生成图的 PDF 版本和绘图数据的逗号分隔值（CSV）文件，供归档或进一步分析。

接下来看估计的阻力系数。

4. 在脚本目录中，输入以下命令：

```
python plot_solve_fors.py <filter.mat 的完整路径>
```

几秒后，你应看到类似下图的图。它显示运行过程中滤波器对阻力系数的估计。回想一下，仿真数据我们用了 Cd 2.2，但估计器以初始 Cd 2.0 和初始 CdSigma 0.1 启动。这可以在图的开头看到：Cd 初始值为 2.0，3-sigma 不确定度边界（图中绿色区域）涵盖 1.7 到 2.3 的范围。随着滤波器运行并纳入测量，它"感知"到给它的 Cd 值不太对，开始把它移向正确的（仿真）值 2.2。与此同时，随着滤波器使用更多测量并对其估计更有"信心"，不确定度边界在减小。

> [图：Cd 估计随时间变化图]

运行滤波器时，你应始终审查运行中所有"非位置和速度"估计参数的此类图。你应确保估计值基于任务经验和参数可能固有的任何物理限制保持在预期范围内（例如 Cd 应始终为正）。你还应确保参数不确定度不会变得太小。如果我们的 FOGM EstimatedParameter 过程噪声（由 SteadyStateSigma 和 HalfLife 导出）太小，就可能发生这种情况。如果不确定度太小，滤波器可能对其参数估计过于自信，无法对可能发生的阻力快速或突然变化做出反应——例如太阳风暴的情况下。这最终可能导致滤波器发散并开始拒绝所有传入的新测量。

我们通常不看位置和速度估计值的类似图，因为它们振荡太剧烈而没有用。星历比较（本教程不涉及）是评估估计位置和速度的重要手段。然而，查看位置和速度不确定度的图很有用，我们接下来就做这个。

5. 在脚本目录中，输入以下命令：

```
python plot_covariance.py <filter.mat 的完整路径>
```

几秒后，你应看到类似下图的图。下图是将为你显示的图的放大。你可以放大你的图查看类似内容。实际上会有两张图，一张位置不确定度，一张速度不确定度，但我们这里只展示位置不确定度图。速度图的外观和解读与位置不确定度图类似。在速度图中，由于沿迹位置与径向速度的相关性，径向速度不确定度将最大（而非沿迹速度）。

> [图：位置不确定度图]

这里我们看到滤波器的 1-sigma 位置不确定度。注意所有曲线都从 100 米开始，这是我们在估计航天器初始 OrbitErrorCovariance 上指定（以平方形式）的值。其次，注意不确定度迅速收敛到"稳态"值：V（速度）分量约 5 米，横向（N）约 2 米，径向（B）约 1 米左右。这种快速收敛发生在滤波器开始纳入测量并改善其状态估计时。协方差曲线的变平是滤波器"收敛"的标志。滤波器正常运行时，应保持收敛状态。由于 GPS_PosVec 数据的测量密度非常一致，协方差应保持相当恒定。其他更随机到达的测量类型会因测量数据的间隙导致状态估计不确定度出现更大波动。如果你把图放大，能观察到"锯齿"模式，尤其在 V 分量中，这是滤波器运行的特征。不确定度在每个测量之间以锯齿状增长，然后每次接受测量时再次塌缩。这反映了过程噪声在没有测量时总是驱动滤波器不确定度增大，而使用测量总是减小滤波器不确定度。稍后如果你愿意，可以试验不同的 ProcessNoiseModel AccelNoiseSigma 值，看看它如何影响这种行为。
