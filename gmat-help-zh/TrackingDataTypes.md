# 轨道确定的跟踪数据类型（TrackingDataTypes）

> 译自 GMAT R2026a 帮助文档 TrackingDataTypes.html

**Tracking Data Types for Orbit Determination** —— 本节描述轨道确定的跟踪数据类型和文件格式。

## 支持的测量类型

GMAT 支持以下用于轨道确定的测量类型。

| GMAT 测量类型名称 | 测量描述 | 测量单位 |
|-------------------|----------|----------|
| Azimuth、Elevation | 天线指向角，适用于 Az/El（方位/俯仰）转台的天线。方位角和仰角的几何关系见参考文献 1 图 9-3。方位角定义为 0 到 360 度变化，沿北轴为 0，向东增大。仰角定义为 -90 到 90 度变化，在北/东平面内为零，向天顶方向增大。 | Degrees |
| BRTS_Doppler | 来自 NASA 跟踪与数据中继卫星系统双边测距应答机系统（BRTS）的双向相干多普勒跟踪。 | Hertz |
| BRTS_Range | 来自 NASA 跟踪与数据中继卫星系统双边测距应答机系统（BRTS）的双向相干测距跟踪。 | Kilometers |
| DSN_PNRange | DSN 伪噪声测距（TRK-2-34 数据类型 14）。 | Range Units |
| DSN_SeqRange | DSN 序列测距（TRK-2-34 数据类型 7）。 | Range Units |
| DSN_TCP | DSN 总计数相位（TRK-2-34 数据类型 17）测量，实现为利用连续相位测量导出的"多普勒"类型测量。此测量类型用于双向和三向跟踪。细节见下文说明。 | Hertz |
| GPS_PosVec | 来自航天器星载 GPS 接收机的地固位置矢量。 | Kilometers |
| Range | 双向应答机测距。包含航天器 `Transponder.HardwareDelay` 的往返测距测量。此测量类型可用于地对空和航天器间（也称星间链路）跟踪。细节见下文说明。 | Kilometers |
| Range_Skin | 双向非应答机测距。不包含航天器 `Transponder.HardwareDelay` 的往返测距测量。此测量类型适用于雷达及其他表面反射（skin-tracking）测量。 | Kilometers |
| RangeRate | 测距变率，单位 km/sec。建模为多普勒计数区间末端与起点的测距测量之差，除以计数区间长度。测量的时间标记在区间末端。此测量类型可用于地对空和航天器间（空-空，也称星间链路）跟踪，并用于单向、双向和三向测距变率跟踪。细节见下文说明。 | Kilometers/sec |
| SN_Doppler | 来自 NASA 跟踪与数据中继卫星（空间网）系统的双向相干用户（在轨）多普勒跟踪。 | Hertz |
| SN_Doppler_Rtn | 来自 NASA 跟踪与数据中继卫星（空间网/空间中继）系统的单向非相干用户返向链路多普勒跟踪。SN_Doppler_Rtn 是空-地多普勒测量，信号发自用户航天器，由 TDRS 航天器接收，并由 TDRS 中继到 TDRS 地面站。 | Hertz |
| SN_DOWD | 来自 NASA 跟踪与数据中继卫星（空间网/空间中继）系统的差分单向返向多普勒跟踪。SN_DOWD 测量通过对同时刻的 TDRS 单向返向多普勒测量求差（相减）构成。 | Hertz |
| SN_Range | 来自 NASA 跟踪与数据中继卫星（空间网）系统的双向相干用户（在轨）测距跟踪。 | Kilometers |
| XEast、YNorth | 天线指向角，适用于 X/Y 转台且 X 旋转轴（即旋转 XEast 角所绕的轴）朝北的天线。XEast 和 YNorth 角的几何关系见参考文献 1 图 9-4。当天线指向天顶时两角均为零。XEast 定义为 -180 到 +180 度变化，YNorth 定义为 -90 到 +90 度变化。 | Degrees |
| XSouth、YEast | 天线指向角，适用于 X/Y 转台且 X 旋转轴（即旋转 XSouth 角所绕的轴）朝东的天线。XSouth 和 YEast 角的几何关系见参考文献 1 图 9-5。当天线指向天顶时两角均为零。XSouth 定义为 -180 到 +180 度变化，YEast 定义为 -90 到 +90 度变化。 | Degrees |

列出的 GMAT 测量类型名称是字符串名称，用于 `ErrorModel`、`AcceptFilter`、`RejectFilter` 和 `TrackingFileSet` 实例中，以及 GMAT GMD 格式跟踪数据文件中，向 GMAT 标识每种测量类型。

### 航天器间跟踪测量

GMAT 支持对某些测量类型进行航天器间（也称"星间链路"）跟踪的仿真和估计。这些测量是在环绕相同或不同引力天体运行的两艘航天器之间进行的测距或多普勒/测距变率跟踪观测。航天器间跟踪目前支持 Range 和 RangeRate 测量类型。航天器间跟踪的 GMAT 跟踪数据文件格式与相应的地对空测量相同，区别在于航天器间测量使用不同的观测类型索引号，具体如下文每种受支持测量类型所示。

要配置两艘航天器进行航天器间跟踪，"跟踪"航天器必须被指定 `Transmitter` 和 `Receiver` 对象。然后用适合航天器间跟踪的 `ErrorModel` 配置跟踪航天器的 Receiver。每个航天器间测量的测量时间标记是跟踪航天器处的 TAIModJulian 测量接收时刻。

另请参见教程《Simulate and Estimate Inter-Spacecraft Tracking》，了解使用航天器间跟踪仿真和估计轨道。由于参与航天器间跟踪的航天器可能处于显著不同的轨道类型，且各自可能需要独特的力建模，GMAT 支持为每个参与方指定单独的力模型和积分器。配置多积分器的细节请参见 `Simulator`、`BatchEstimator` 和 `ExtendedKalmanFilter` 资源的 `Propagator` 字段。

## GMAT 跟踪数据文件格式

GMAT 使用一种称为"GMAT 测量数据文件"（GMAT Measurement Data File，简称 GMD 文件）的原生 ASCII 跟踪数据文件格式。每个 GMD 文件由一系列空格分隔的 ASCII 记录组成。以下各节提供每种观测类型的 GMD 文件格式细节。单个 GMD 文件可以包含下述一种或多种记录类型，但斜坡记录必须在单独的文件中。

有关下文引用的 TRK-2-34 原始数据格式的更多细节，请查阅参考文献 2。

### 角度测量

所有角度测量类型（Azimuth、Elevation、XEast、YNorth、XSouth 和 YEast）共享相同的 GMD 文件格式。通用角度观测以度为单位，表示参考文献 1 图 9-2 所示测站地平参考系中的旋转角。角度观测数据的 GMD 记录格式如下表所示。

| 字段 | 描述 |
|------|------|
| 1 | 观测接收时刻，TAIModJulian |
| 2 | 观测类型名称——Azimuth、Elevation、XEast、YNorth、XSouth 或 YEast |
| 3 | 观测类型索引号：9016 = Azimuth，9017 = Elevation；9018 = XEast，9019 = YNorth；9020 = XSouth，9021 = YEast |
| 4 | 下行地面站 pad ID |
| 5 | 航天器 ID |
| 6 | 角度测量值（度） |

### 双边测距应答机系统（BRTS）测量

双边测距应答机系统（BRTS）由固定在地球表面不同位置的一组应答机组成。TDRS 卫星像跟踪在轨航天器一样跟踪 BRTS 应答机。给定 BRTS 应答机的已知位置，所得的测距和多普勒测量可用于确定 TDRS 轨道。BRTS 测量实际上与 SN 用户测量（见下文）相同，因为地面上的 BRTS 的行为与空间中的 SN 用户完全一致。

关于分配 TDRS 航天器 ID 的规则，请参见下文说明。

BRTS_Range 和 BRTS_Doppler 的测量路径起始于 TDRSS 地面终端，沿上行链路到达 TDRSS 航天器，由 TDRS 沿前向链路中继到地面上的 BRTS 天线。BRTS 应答机接收并沿返向路径转发信号到（通常是同一个）TDRSS 航天器，然后该航天器沿下行路径将信号中继到 TDRSS 地面终端（通常与发射地面站相同）。

#### BRTS 多普勒测量

BRTS_Doppler 观测数据的 GMD 记录格式如下表所示。

| 字段 | 描述 |
|------|------|
| 1 | 观测接收时刻，TAIModJulian |
| 2 | 观测类型名称——BRTS_Doppler |
| 3 | 观测类型索引号——9025 = BRTS_Doppler |
| 4 | 测量路径。格式为 { XmitGroundStation ForwardTDRS BRTSGroundStation ReturnTDRS RecvGroundStation } |
| 5 | 标称 BRTS 发射频率（Hz） |
| 6 | BRTS 发射频段指示符——0 = 未知，1 = S 频段，2 = X 频段，3 = Ka 频段，4 = Ku 频段，5 = L 频段 |
| 7 | TDRS 业务 ID——'SA1'、'SA2' 或 'MA' |
| 8 | MA 业务的跟踪器类型（0 = 传统型，1 = TDRS-K） |
| 9 | S 频段多址返向（SMAR）下行频率 ID |
| 10 | 多普勒计数区间（秒） |
| 11 | 多普勒观测值（Hz） |

### DSN 伪噪声测距

DSN TRK-2-34 伪噪声测距使用 `DSN_PNRange` 测量类型。DSN_PNRange 是以测距单位（range units）计量的模糊测距观测。无模糊往返测距的计算由 GMAT 内部使用预测航天器状态和 GMD 文件中提供的测距模值完成。注意，如果初始航天器状态很差，可能会计算出错误的测距区间数，导致计算出错误的实测往返测距。通常可以通过提供更精确的初始状态（如果有）来解决。DSN_PNRange 跟踪数据的 GMD 记录格式如下表所示。

| 字段 | 描述 |
|------|------|
| 1 | 观测接收时刻，TAIModJulian |
| 2 | 观测类型名称——DSN TRK-2-34 类型 14 伪噪声测距 = DSN_PNRange |
| 3 | 观测类型索引号——9033 = DSN_PNRange |
| 4 | 跟踪测量路径。格式为 { XmitGroundStation Spacecraft RecvGroundStation } |
| 5 | 以测距单位计的测距观测量（来自 TRK-2-34 PN 测距跟踪 CHDO 的 *meas_rng* 值） |
| 6 | 发射延迟（秒）。为 *ul_stn_cal* + *ul_zheight_corr* 之和，其中 *ul_stn_cal* 取自 PN 测距跟踪 CHDO，*ul_zheight_corr* 取自 CHDO 134。*ul_stn_cal* 的值应按下文所示方法从测距单位转换为秒。 |
| 7 | 接收延迟（秒）。为 *dl_stn_cal* + *dl_zheight_corr* 之和，其中 *dl_stn_cal* 取自 PN 测距跟踪 CHDO，*dl_zheight_corr* 取自 CHDO 134。*dl_stn_cal* 的值应按下文所示方法从测距单位转换为秒。 |
| 8 | 上行频段指示符——0 = 未知，1 = S 频段，2 = X 频段，3 = Ka 频段，4 = Ku 频段，5 = L 频段。即 CHDO 134 的 *ul_band* 值。 |
| 9 | 下行频段指示符——0 = 未知，1 = S 频段，2 = X 频段，3 = Ka 频段，4 = Ku 频段，5 = L 频段。即 CHDO 134 的 *vld_dl_band* 值。 |
| 10 | 发射频率（Hz）。见下文说明。 |
| 11 | 测距模值（来自 TRK-2-34 PN 测距跟踪 CHDO 的 *rng_modulo*） |

#### 计算 PN 测距值的构成

GMAT 通过以下过程确定计算 PN 测距值：

1. GMD 记录的测量观测时刻表示信号到达接收机电子设备的时刻。信号到达天线的时刻由 GMD 记录观测接收时刻减去 GMD 记录接收延迟得到。
2. 从调整后的接收时刻出发求解光行时方程，得到发射时刻和总往返光行时。光行时解给出信号在发射时离开天线的时刻。
3. 信号在发射时离开天线的时刻减去发射延迟，得到信号离开发射天线电子设备的时刻。
4. 在电子设备发射与接收时刻之间对频率积分（如适用，使用斜坡表）。这给出以测距单位计的总往返信号路径。

### DSN 序列测距

DSN TRK-2-34 序列测距使用 `DSN_SeqRange` 测量类型。DSN_SeqRange 是以测距单位计量的模糊测距观测。无模糊往返测距的计算由 GMAT 内部使用计算的航天器状态和 GMD 文件中提供的测距模值完成。注意，如果初始航天器状态很差，可能会计算出错误的测距区间数，导致计算出错误的实测往返测距。通常可以通过提供更精确的初始状态（如果有）来解决。DSN_SeqRange 跟踪数据的 GMD 记录格式如下表所示。

| 字段 | 描述 |
|------|------|
| 1 | 观测接收时刻，TAIModJulian |
| 2 | 观测类型名称——DSN TRK-2-34 类型 7 序列测距 = DSN_SeqRange |
| 3 | 观测类型索引号——9004 = DSN_SeqRange |
| 4 | 下行地面站 pad ID 或跟踪航天器 ID |
| 5 | 航天器 ID |
| 6 | 测距观测量（来自 TRK-2-34 序列测距 CHDO 的 *meas_rng* 或 *rng_obs*，已施加适当修正） |
| 7 | 上行频段指示符——0 = 未知，1 = S 频段，2 = X 频段，3 = Ka 频段，4 = Ku 频段，5 = L 频段 |
| 8 | 上行频率（Hz） |
| 9 | 测距模值（来自 TRK-2-34 序列测距 CHDO 的 *rng_modulo*） |

#### 计算序列测距值的构成

GMAT 通过以下过程确定计算 PN 测距值：

　　computed range = C · ∫(t1→t3) f_T(t) dt，mod M　　(RU)

其中：

- t1、t3 = 分别为发射和接收历元
- f_T = 地面站发射频率
- C = 与发射机相关的常数（X 频段为 221/1498，S 频段为 1/2）
- M = 测距码长度（RU）

### DSN 总计数相位

DSN TRK-2-34 总计数相位使用 `DSN_TCP` 测量类型。此测量类型用于双向和三向跟踪。如下所示，以 Hz 计量的 GMAT 多普勒测量类型由连续的总计数相位（TCP）观测导出。

　　导出的"多普勒"观测量 = −[φ(t_3e) − φ(t_3s)] / (t_3e − t_3s) = −[φ(t_3e) − φ(t_3s)] / DCI　　(Hz)

其中：

- t_3s、t_3e = 接收区间的起点和终点
- DCI = 多普勒计数区间（秒）
- φ = 总计数相位（来自类型 17 TRK-2-34 记录）

| 3 | 观测类型索引号——9006 = DSN_TCP |

| 6 | 多普勒计数区间（秒） |
| 7 | 观测值——由总计数相位（TCP）TRK-2-34 类型 17 测量导出的多普勒观测量 |

#### 计算 TCP 多普勒值的构成

GMAT 通过以下过程确定计算 TCP 多普勒值：

　　C = −M_2/(t_3e − t_3s) · ∫(t_1s→t_1e) f_T(t_1) dt_1 = −M_2(t_1e − t_1s)/DCI · f̄_T　　(Hz)

其中：

- t_1s、t_1e = 发射区间的起点和终点
- f_T = 发射频率
- M_2 = 应答机转发比（通常 S 频段为 240/221，X 频段为 880/749）
- DCI = (t_3e − t_3s) = 多普勒计数区间
- f̄_T ≡ ∫(t_1s→t_1e) f_T(t_1) dt_1 / (t_1e − t_1s) = 平均发射频率

注意，(t3e - t3s) 称为多普勒计数区间。该值从 GMD 文件记录读取（用于估计），在仿真时是 `TrackingFileSet` 资源上的输入字段 `SimDopplerCountInterval`。

### 空间网（跟踪与数据中继卫星系统）测量

跟踪与数据中继卫星系统（TDRSS）由地球同步轨道上的航天器星座组成，为低地球轨道提供近连续覆盖。TDRSS 航天器用于将低轨航天器的数据中继到地面。TDRSS 航天器也用于跟踪低轨航天器，TDRSS 提供多种在 GMAT 中受支持用于轨道确定（OD）的测量类型。

> **注意**：TDRSS 测量模型中的某些常数取决于用户业务（SA1、SA2 或 MA）和 TDRS 航天器 ID。用户业务在 GMD 文件跟踪数据记录中明确指示。GMAT 将尝试从 `Spacecraft` 资源的 `Id` 参数确定 TDRS 航天器 ID。为使 TDRS 测量在所有情况下正常工作，用户在为 TDRS 航天器指定 `Spacecraft.Id` 参数时必须遵守以下约定之一：
>
> - 用户可以将 TDRS SIC 指定为 TDRS 航天器 Id。GMAT 将从相应的 TDRS 航天器 SIC 推断 TDRS ID。
> - 或者，用户可以按 "*<string><nn>*" 格式指定 TDRS `Spacecraft.Id`，其中 *<nn>* 是表示 TDRS ID 的一位或两位数字。ID 的 *<string>* 部分可以是任意字符串。例如，将航天器 `Id` 参数设为 "TDRS09"、"TD09" 或 "TDRS9" 都能正确地将航天器标识为 TDRS-9（TDRS ID = 9）。
>
> 不遵守这些约定之一可能导致某些多普勒测量计算错误。如果 GMAT 无法从航天器 `Id` 参数确定 TDRS ID，将在日志文件中发出警告消息。

对于所有 TDRS 测量类型，介质（电离层和对流层）修正仅施加于 TDRS 到地面的跟踪链路。用户到 TDRS（空-空）跟踪链路不计算介质修正。

#### 空间网（TDRSS）单向返向多普勒

TDRSS 非相干单向用户返向多普勒跟踪使用 `SN_Doppler_Rtn` 测量类型。SN_Doppler_Rtn 的测量路径起始于在轨用户航天器，沿返向链路到达 TDRSS 航天器，由 TDRS 沿下行链路中继到 TDRSS 地面终端。

此测量构成为用户航天器到 TDRS 到地面的单向平均测距变率，与地面到 TDRS 到地面的双向平均测距变率的组合。请注意，GMAT 在太阳系质心（SSB）系中构建光行时解，这要求在用户到 TDRS 到地面的单向链路上建模 ET-TAI 修正。无论 `TrackingFileSet` 的 `UseETminusTAI` 标志如何设置，GMAT 都会自动在该链路上施加 ET-TAI。该标志将按用户设置（True 或 False）施加于测量的双向测距变率分量。

#### 空间网（TDRSS）差分单向返向多普勒

TDRSS 差分单向返向多普勒跟踪使用 `SN_DOWD` 测量类型。SN_DOWD 通过对同时刻的 SN 单向返向多普勒测量求差构成。SN_DOWD 的构成需要两条同时进行的、至少有部分相同时间标记的 SN 单向返向跟踪弧段。GMAT 使用 SN_Doppler_Rtn 测量模型对每条单向返向多普勒链路建模，然后对建模的单向多普勒测量求算术差，得到计算的 DOWD 测量。

SN_DOWD 数据的 GMD 记录格式如下表所示。注意，同时刻单向测量的求差必须在 GMAT 外部、在构成 GMD 记录时完成。

| 1 | 观测接收时刻，TAIModJulian |
| 2 | 观测类型名称——SN_DOWD |
| 3 | 观测类型索引号——9028 |
| 4 | 测量路径；格式为 { UserSpacecraft, ReturnTDRS1, RecvGroundStation1, ReturnTDRS2, RecvGroundStation2 } |
| 5 | ReturnTDRS1 路径标称用户发射频率（Hz） |

| 11 | ReturnTDRS2 路径标称用户发射频率（Hz） |

#### 空间网（TDRSS）双向测距

TDRSS 相干双向测距跟踪使用 `SN_Range` 测量类型。SN_Range 的测量路径起始于 TDRSS 地面终端，沿上行链路到达 TDRSS 航天器，由 TDRS 沿前向链路中继到用户航天器。用户航天器接收并沿返向路径转发信号到（通常是同一个）TDRSS 航天器，然后该航天器沿下行路径将信号中继到 TDRSS 地面终端（通常与发射地面站相同）。SN_Range 数据的 GMD 记录格式如下表所示。

| 字段 | 描述 |
|------|------|
| 1 | 观测接收时刻，TAIModJulian |
| 2 | 观测类型名称——SN_Range |
| 3 | 观测类型索引号——9000 = SN_Range |
| 4 | 测量路径；格式为 { XmitGroundStation, ForwardTDRS, UserSpacecraft, ReturnTDRS, RecvGroundStation } |
| 5 | 总往返测距测量值（km） |
