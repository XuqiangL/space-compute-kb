# 运行任务并分析结果（DSN_Estimation_Run_the_mission_and_analyze_the_results）

> 译自 GMAT R2026a 帮助文档 DSN_Estimation_Run_the_mission_and_analyze_the_results.html

用于运行任务的脚本片段如下所示。

```
BeginMissionSequence
 
RunEstimator bat
```

**中文说明**：BeginMissionSequence 标志命令段开始，RunEstimator bat 用批处理估计器 bat 执行估计。

第一行脚本 `BeginMissionSequence` 是必需命令，表示 GMAT 脚本的"命令"部分已开始。第二行脚本发出 `RunEstimator` 命令，以"创建并配置批处理估计器对象"一节中定义的 bat `BatchEstimator` 资源为参数。这告诉 GMAT 使用 bat 资源指定的参数执行估计。

我们现在已完成所有脚本片段。完整脚本清单请参见 samples 文件夹中的 `Tut_Orbit_Estimation_using_DSN_Range_and_Doppler_Data.script` 文件。现在可以运行脚本了。点击 Save,Sync,Run 按钮。考虑到我们处理的数据量、任务轨道和力模型选择，脚本应在约 1-2 分钟内执行完毕。

我们以多种方式分析此脚本的结果。第一小节分析消息窗口输出，第二小节查看观测残差图，第三小节分析批处理估计报告，最后第四小节讨论如何使用 MATLAB 输出文件的内容分析估计过程的结果。

如前所述，OLSE 过程可以编辑（即移除）某些数据，使其不作为估计算法的一部分使用。有五种情况可能导致数据点被编辑。上面的输出针对每种情况指定了多少数据点被编辑。我们现在讨论这五种情况的含义。

第一种情况"No Computed Value Configuration Available"（无可用计算值配置）意味着 GMAT 读入了一些测量数据，但 GMAT 脚本中未定义相应的跟踪配置。因此 GMAT 无法形成测量的计算值 C。例如，如果我们的脚本未定义与 GMD 文件中某些数据对应的 `GroundStation` 对象，就可能发生这种情况。由于我们已定义了所需的一切，没有数据点因此情况被编辑。

第二种情况"Out of Ramp Table Range"（超出斜坡表范围）意味着在求解光行时方程时，GMAT 需要知道某地面站在斜坡表未覆盖时刻的发射频率（斜坡表在我们的 `TrackingFileSet` 资源 `DSNsimData` 中指定）。查看输入 GMD 文件，测量时刻范围为 27253.5004166... 到 27274.5004166666... TAIMJD。由于斜坡表在 27252 TAIMJD（约比第一个测量早 1.5 天）对所有三个地面站都有斜坡记录，且我们的先验笛卡尔状态估计相当好，因此没有测量因此情况被编辑是合理的。

第三种情况"Signal Blocked"（信号遮挡）表示在考虑当前状态估计的情况下，GMAT 计算出某测量链路的测量不可能，因为信号被"遮挡"。实际上信号不必真的被遮挡，只需违反给定地面站的最小仰角约束即可。考虑某时刻 GDS 到 Sat 到 GDS 的双向测距测量。如果 GDS 到 Sat 的仰角为 6 度，该测量将被编辑剔除，因为 `GDS.MinimumElevationAngle` 字段指定的最小仰角设为 7 度。由于在我们的仿真中，我们指定只输出满足此 7 度约束的数据，因此没有数据因此情况被编辑是合理的。

第四种情况"Initial RMS Sigma Filter"（初始 RMS sigma 滤波器）对应 GMAT 初始迭代的 OLSE 处理。如前所述，OLSE 的完整描述见 `BatchEstimator` 帮助中的"外循环 sigma 编辑（OLSE）的行为"讨论。如帮助中所述，对于初始迭代，满足以下条件的数据被编辑：

　　|加权测量残差| > OLSEInitialRMSSigma

其中给定测量的加权测量残差为：

　　(O-C)/NoiseSigma

其中 NoiseSigma 是我们创建各 `ErrorModel` 资源时设置的输入。

我们注意到，对于良好的轨道解，加权测量残差的值约为 1。由于我们的先验状态估计与真值相差不远，且我们将 `OLSEInitialRMSSigma` 设为非常大的值 10000，我们预计不会有数据因此情况被编辑。

第五种情况"Outer-Loop Sigma Editor"（外循环 sigma 编辑器）对应 GMAT 第二次或后续迭代的 OLSE 处理。由于我们正在分析的输出是批处理估计器的初始迭代，因此情况被编辑的数据点数为 0。我们将在分析后续迭代的输出时讨论第二次或后续迭代的 OLSE 处理。

```

   PredictedRMS residuals for next iteration: 0.977684716761
```

**中文说明**：本次迭代加权 RMS 残差约 1460，最佳 RMS 相同，预测下次迭代约 0.978。

出于我们对初始第 0 次迭代讨论过的相同原因，如预期，没有数据点因"No Computed Value Configuration Available"或请求频率"Out of Ramp Table Range"而被编辑。同样出于第 0 次迭代讨论过的原因，没有数据点因信号遮挡而被编辑是合理的。注意，没有数据点因"Initial RMS Sigma Filter"情况被编辑。这符合预期，因为该情况仅在初始第 0 次迭代编辑数据。最后我们注意到，在本例中，1348 个数据点中有 1 个因 OLSE 条件被编辑。由于仿真步骤中添加噪声的随机性，您可能会看到更多或更少的点被编辑。

如 `BatchEstimator` 帮助中"外循环 sigma 编辑（OLSE）的行为"一节所述，满足以下条件的数据被编辑：

　　|加权测量残差| > OLSEMultiplicativeConstant * WRMSP + OLSEAdditiveConstant

其中：

　　WRMSP 是上一次迭代结束时计算的预测加权 RMS。

在"创建并配置批处理估计器对象"一节中，我们选择 OLSEMultiplicativeConstant = 3 和 OLSEAdditiveConstant = 0，因此上式变为：

　　|加权测量残差| > 3 * WRMSP

只有少数点被编辑剔除是好迹象。如果太多数据被编辑剔除，即使加权 RMS 值很好，也表明您的状态估计可能有问题。接下来，GMAT 输出与第 1 次迭代关联的一些均方根（RMS）统计数据。

## 观测残差图

GMAT 按每次迭代、每个地面站、每种测量类型生成图。我们详细说明其含义。脚本首次运行时，最先出现的是第 0 次迭代残差图。这意味着在计算 'O-C' 观测残差时，GMAT 使用先验状态计算残差的计算值 C。如附录 B —— 第 0 次迭代的观测残差图所示，共有 6 幅第 0 次迭代残差图。3 个站各有一幅测距残差图和一幅多普勒残差图。第 1 次迭代处理完成后，GMAT 输出第 1 次迭代残差，如附录 C —— 第 1 次迭代的观测残差图所示。如前所述，虽然对此脚本 GMAT 用两次迭代收敛，但实际的第 2 次迭代残差既不计算也不绘制。

我们现在分析 CAN 测距和多普勒残差。对于第 0 次迭代，测距残差约在 11000 到 31000 RU 之间变化。残差这么大是因为我们的先验状态估计被人为地从真值扰动。图上有多个迹象表明 GMAT 尚未收敛。首先，残差具有近似线性结构。如果您正确建模了动力学和测量，图应呈现无结构的随机外观。此外，残差有偏，即均值不为零。对于建模良好的系统，残差均值应接近零。最后，测距残差的量级明显过大。回想一下，在"创建并配置地面站及相关参数"一节中，我们将 CAN 测距测量的 1 sigma 测量噪声设为 10.63 RU。因此，对于大样本测量，我们大致预期绝大多数测量将位于约 -32 到 +32 RU 之间。看一下第 1 次迭代的 CAN 测距残差，大致正是如此。

第 0 次迭代 `CAN` 多普勒残差约在 0.0050 到 0.01535 Hz 之间。与测距第 0 次迭代残差的情况一样，多普勒残差有偏表明 GMAT 尚未收敛。回想一下，在"创建并配置地面站及相关参数"一节中，我们将 `CAN` 多普勒测量的 1 sigma 测量噪声设为 0.0282 Hz。因此，对于大样本测量，我们大致预期绝大多数测量将位于约 -0.0846 到 +0.0846 之间。看一下第 1 次迭代的 `CAN` 多普勒残差，大致正是如此。

关于这些图有一个重要细节需要注意。GMAT 只绘制实际用于计算解的数据点的残差。回想一下，对于第 0 次迭代，1348 个测量全部用于计算轨道状态，即没有数据点被编辑。因此，如果您数一下 6 幅第 0 次迭代图上的所有数据点，会发现有 1348 个点。第 1 次迭代的情况不同。回想一下，对于第 1 次迭代，1348 个测量中有 1347 个用于计算轨道状态，即 1 个数据点被编辑。因此，如果您数一下 6 幅第 1 次迭代图上的所有数据点，会发现有 1347 个点。如果您希望生成同时包含未编辑和已编辑测量的图，需要使用 MATLAB 输出文件自行生成，如"Matlab 输出文件"一节所述。

我们注意到这些图具有一些交互功能。将鼠标悬停在感兴趣的图上然后右键点击，您会看到四个选项：可以开关网格线和图例，可以将图数据导出到文本文件，还可以将图图像导出到 bmp 文件。

## 批处理估计器输出报告

在"创建并配置批处理估计器对象"一节中创建 BatchEstimator 资源 bat 时，我们指定输出文件名为 'Orbit Estimation using DSN Range and Doppler Data.report'。转到 GMAT 的 'output' 目录并打开此文件，最好使用 Notepad++ 之类的编辑器，以便轻松滚动查看数据行。

报告的前约 150 行主要是我们输入脚本的参数回显，如初始航天器状态、力模型、积分器设置、要处理的测量类型等。

在输入数据回显之后，输出报告包含与初始第 0 次迭代关联的测量残差。在文件中搜索 'ITERATION 0: MEASUREMENT RESIDUALS' 字样可找到相关输出的起始位置。此输出节包含估计过程中可能使用的所有测量（包括未编辑和已编辑的）的信息。每行数据对应一个测量。对于每个测量，输出告诉您以下信息：

- 迭代号
- 记录号
- UTC 公历格式的历元
- 观测类型。'DSN_SeqRange' 对应 DSN 序列测距，'DSN_TCP' 对应 DSN 总计数相位导出多普勒。
- 参与方。例如 '22222,11111,22222' 告诉您测量来自 CAN 到 Sat 到 CAN 链路。
- 编辑判据
- 观测值（O）
- 计算值（C）
- 观测残差（O-C）
- 仰角

我们之前讨论过编辑判据，特别是讨论了数据可能被编辑的各种原因。如果残差记录未显示编辑代码，意味着该数据未被编辑，且本次迭代中该数据被用于计算状态估计。

注意，如果任何测量的仰角低于我们输入的 7 度判据，该测量将被编辑，因为信号被视为"遮挡"。对于测距数据，我们会看到 Bn，其中 n 是指定链路号的整数。对于我们的双向测距数据类型，有两条链路：上行链路用整数 1 表示，下行链路用整数 2 表示。因此，如果在此字段中看到 "B1"，意味着信号在上行链路被遮挡。相应地，对于多普勒数据，我们也会看到 Bn，但整数 n 为 1 或 2，取决于遮挡发生在起始路径（n=1）还是结束路径（n=2）。

在所有单独的第 0 次迭代残差打印完毕后，会打印出如下所示的四份不同的第 0 次迭代观测摘要报告：

- 按站和数据类型的观测摘要（Observation Summary by Station and Data Type）
- 按数据类型和站的观测摘要（Observation Summary by Data Type and Station）
- 按站的观测摘要（Observation Summary by Station）
- 按数据类型的观测摘要（Observation Summary by Data Type）

在所有观测摘要打印完毕后，打印出通过处理先前残差信息获得的更新状态和协方差信息。输出还包含本次迭代状态估计各分量变化量的统计信息。

此时，输出内容对下一次迭代重复。新状态估计用于计算新残差，过程重新开始。当估计器收敛或发散时，过程停止。

我们现在举例说明如何使用此报告。在"消息窗口输出"一节中，我们注意到对于第 1 次迭代，某些测量因 OLSE 判据被编辑。让我们更详细地研究一下。什么类型的数据被编辑了？来自哪个站？该站的这种数据类型会有问题吗？我们查看第 1 次迭代的"按站和数据类型的观测摘要"。我们看到来自 `CAN` 站的一个测距测量被编辑。`GDS` 测距测量的平均残差和 1-sigma 标准差分别为 -0.222339 和 10.082896 RU。`MAD` 测距测量的平均残差和 1-sigma 标准差分别为 0.199925 和 10.205535 RU。

现在我们知道问题出在 `GDS` 和 `MAD` 测距测量，我们查看第 1 次迭代的详细残差输出，以确定这些测量发生的时刻。我们可以搜索 OLSE 关键字来帮助查找。我们确定一个 `CAN` 测距测量在 02 Sep 2015 04:00:00.000 UTCG 被编辑，其观测残差为 -33.161377 RU。这只比 3-sigma 值略大，我们得出结论，`CAN` 测距测量没有真正的问题。这只是正常的统计涨落。

提醒您，当您自己运行时，被编辑的数据点数量可能不同。这是因为仿真时 GMAT 使用随机数生成器，您将使用不同的数据集。

## Matlab 输出文件

在"创建并配置批处理估计器对象"一节中创建 `BatchEstimator` 资源 bat 时，我们选择了 MATLAB 输出文件名 `Orbit Estimation using DSN Range and Doppler Data.mat`。默认情况下，此文件在 GMAT 的 'output' 目录中创建。只有在安装了 MATLAB 并正确配置与 GMAT 的接口时，才会创建此文件。

启动 MATLAB 会话。将目录切换到 GMAT 'output' 目录，然后在 MATLAB 命令提示符下输入以下内容。

```
>> load 'Orbit Estimation using DSN Range and Doppler Data.mat'
```

**中文说明**：在 MATLAB 中加载估计输出的 .mat 文件。

文件加载后，输入以下命令获取此文件中可用变量名的列表。

```
>> whos
```

**中文说明**：列出 mat 文件中的变量。

您应该会看到类似以下的内容：

```
>> whos
  Name                  Size              Bytes  Class     Attributes

  EstimationConfig      1x1                2894  struct              
  Iteration             2x1             1479640  struct              
  Observed              1x1             1232484  struct              
```

**中文说明**：mat 文件包含三个结构体——EstimationConfig（估计配置）、Iteration（每次迭代数据，2 次迭代）、Observed（观测数据）。

每个变量都是包含多个字段的结构体，字段中存有测量、残差、编辑标志、状态信息和其他有用分析数据的数组。批处理估计器 MATLAB 文件内容的完整细节可在 BatchEstimator 资源文档的"批处理估计器 MATLAB 数据文件"一节中找到。

您可以使用 MATLAB 文件中的数据进行自定义绘图和统计分析。例如，要生成第二次迭代所有测距残差的图，可以执行以下操作：

```
>> I = find(strcmp(Observed.MeasurementType, 'DSN_SeqRange'));
>> t = Observed.EpochUTC(1,I);
>> y = cell2mat(Iteration(2).Residual(I));
>> plot(t, y, 'go');
>> datetick
```

**中文说明**：找出所有 DSN_SeqRange 类型测量的索引，取其 UTC 历元和第 2 次迭代的残差，绘制残差随时间变化的图（绿色圆点），并将横轴转为日期格式。
