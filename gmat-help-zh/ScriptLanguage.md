# 脚本语言（ScriptLanguage）
> 译自 GMAT R2026a 帮助文档 ScriptLanguage.html

脚本语言 —— GMAT 脚本语言。

## 脚本结构

GMAT 脚本是一个由合法脚本语法元素组成的文本文件，例如初始化语句、任务序列（Mission Sequence）命令和注释。这些语法元素将在本规范的后续部分中介绍。

在最高层面上，GMAT 脚本由两个部分组成：初始化（Initialization）部分和任务序列（Mission Sequence）部分。这两个部分都包含语句，但它们对哪类语句合法有不同的规则。`BeginMissionSequence` 命令定义了任务序列部分的开始。

> [图：GMAT 脚本编辑器中显示的脚本结构示例]

### 初始化（Initialization）

脚本文件中的第一个部分称为初始化部分，负责创建资源（Resource）并设置其初始状态。初始化部分可以包含以下类型的语句：

- 资源创建语句（`Create` 语句）
- 初始化语句

本部分只允许字面量赋值；不执行任何命令，也不计算任何参数。在图形界面（GUI）中，初始化部分直接映射到资源（Resources）树。当脚本被加载时，本部分中创建的所有资源以及设置的所有字段都会在 GUI 中显示为资源。

### 任务序列（Mission Sequence）

任务序列部分包含任务序列，即任务运行时按顺序执行的 GMAT 命令列表。任务序列部分可以包含以下类型的语句：

- 命令语句

任务序列从第一个 `BeginMissionSequence` 命令处开始；因此，它必须是脚本文件中的第一条命令语句。为了向后兼容，如果缺少 `BeginMissionSequence` 命令，任务序列将从遇到的第一条命令开始。

在 GUI 中，任务序列部分直接映射到任务（Mission）树。脚本中的每条语句（`BeginScript`/`EndScript` 复合命令除外）都显示为树中的单个元素。

## 基本语法

### 源文本

GMAT 脚本由单个文件组成，文件内容只能包含 7 位 US-ASCII 字符集中的字符。脚本语言区分大小写，因此下面这一行会创建四个不同的变量（Variable）资源：

`Create Variable x X y Y`

脚本语言以行为单位。一行可以是：

- 空行
- 注释（见下文"注释"）
- 语句（见"语句"）

语句行可以使用续行标记（"`...`"）拆分到多个物理行上。

### 行终止

脚本行由以下任一 ASCII 字符序列终止：

- 换行符 LF（十六进制：0A）
- 回车符 CR（十六进制：0D）
- 回车符后跟换行符（十六进制：0D0A）

### 空白字符

空白字符可以出现在任何行的上方或下方、行内任何语句的前后，以及脚本中的许多其他位置。以下字符被识别为空白字符：

- 空格（十六进制：20）
- 水平制表符（十六进制：09）

水平制表符在字符串字面量中会被保留，但在某些其他上下文（例如方程、注释）中会被替换为空格。

### 注释

注释以百分号（"`%`"，十六进制：25）开始，一直延续到行尾。脚本语言中没有多行注释或嵌入式注释。

### 文件路径

有几种资源类型的字段接受文件路径作为输入。此类路径的一般语法在语言中是通用的，但某些具体行为由各资源自行规定。

在 GMAT 中，正斜杠和反斜杠可以互换使用，并且可以在同一路径中混用。以下三个路径被视为完全相同：

```
data/planetary_ephem/spk/de421.bsp
data\planetary_ephem\spk\de421.bsp
data\planetary_ephem/spk\de421.bsp
```

以上三行是等价路径的示例：正斜杠、反斜杠以及两者混用的写法指向同一个文件。

绝对路径会原样传递给底层操作系统，仅对斜杠进行规范化处理。

对于输入文件，相对路径首先相对于脚本文件解析，然后相对于各资源类型单独定义的位置解析，该位置通常在 GMAT 启动文件中定义。详细信息请参见各资源类型的参考文档。

对于输出文件，相对路径相对于脚本文件解析。如果只指定了文件名，文件将被放置到 GMAT 启动文件中定义的输出位置（通常是 GMAT 的 `output` 文件夹）。

文件路径写作字符串字面量（见"数据类型"下的"字符串"）。如果路径包含空格，引号是必需的；否则引号是可选的。
## 数据类型

### 字面量

#### 整数

整数写作一串纯数字，不带小数点。允许前导零和前置符号（`+` 或 `-`）。不允许使用科学计数法。

#### 实数

实数可以采用以下任一格式书写：

- `12`（整数形式）
- `12.5`（小数形式）
- `1.25e1` 或 `1.25e-1`（科学计数法）

在所有格式中，基数都可以包含前导或尾随零。在科学计数法中，指数可以带前置符号（`+` 或 `-`），可以包含前导零，但不能包含小数点。指数分隔符不区分大小写（即 "`e`" 或 "`E`" 均可）。

#### 字符串

字符串字面量以单引号字符（"`'`"，十六进制：27）作为定界符。

除下列例外情况外，语言支持的所有字符都允许出现在字符串中。脚本语言没有转义字符或字符替代序列（例如用 "`\n`" 表示换行）。

在初始化部分中，字符串字面量不允许包含以下字符：

- 某些不可打印字符（NUL、SUB）（十六进制：00、1A）
- 行终止字符（LF、CR）（十六进制：0A、0D）
- 百分号（"`%`"）（十六进制：25）

在任务序列部分中，字符串字面量不允许包含以下字符：

- 某些不可打印字符（NUL、SUB）（十六进制：00、1A）
- 行终止字符（LF、CR）（十六进制：0A、0D）
- 百分号（"`%`"）（十六进制：25）

引号通常是可选的，但在初始化部分中，如果字符串包含空白字符、任何脚本语言符号或任何 GMAT 可识别的元素（例如关键字、资源名称），则引号是必需的。在任务序列部分中，除上述情形外，如果字符串包含数学运算符和某些不可打印字符，引号也是必需的。我们建议为所有字符串字面量加上引号。

#### 布尔值

支持以下布尔值：

- `true`（别名：`on`）
- `false`（别名：`off`）

布尔字面量不区分大小写。

#### 枚举值

许多资源字段接受枚举值。例如，`Spacecraft`.`DateFormat` 接受 10 个值之一（`A1ModJulian`、`A1Gregorian` 等）。枚举值写作字符串字面量。引号始终是可选的，因为枚举值都不含空格或特殊字符。

#### 引用

对资源及资源参数的引用通过资源或资源参数的名称来表示。引用写作字符串字面量。引号始终是可选的，因为资源名称和参数不能包含空格或特殊字符。

### 资源

#### 资源类型

GMAT 中的资源是某种基础资源类型的实例，它们被赋予用户定义的名称，并独立于同类型的其他资源存储数据。资源类型包括 `Spacecraft`、`GroundStation` 和 `Variable` 等。资源类型不能直接使用，必须先用 `Create` 语句实例化。例如：

`Create Spacecraft aSat`

在示例中，`Spacecraft` 是资源类型，`aSat` 是资源。这类似于面向对象编程中类和对象的概念：GMAT 的资源类型类似于类，资源类似于对象。

#### 命名规则

资源的命名必须遵循以下规则：

- 名称必须由 ASCII 字母、数字或下划线字符（"`_`"）组成。对应的十六进制值为 30–39、41–5A、5F 和 61–7A。
- 名称必须以字母开头（`A`–`Z` 或 `a`–`z`，十六进制：41–5A 或 61–7A）
- 名称不能是保留关键字或命令名

#### 名称遮蔽（Shadowing）

当同一名称在脚本中用于多个用途时，将应用遮蔽规则来确定对该名称的引用如何解释。

资源名称在脚本内必须唯一。如果脚本试图创建多个具有相同名称（区分大小写）的资源，则脚本中第一个使用该名称的 `Create` 语句会被执行，后续语句都会被忽略。该冲突会在警告消息中注明。

> **注意**：GMAT 不会检查资源名称与函数名称是否唯一。请小心为用户自定义的 GMAT、MATLAB 和 Python 函数使用唯一的名称，以避免名称冲突。

命令名和关键字是保留的，不能用作资源名称。关键字列表请参见"关键字"一节。

内置函数名（如 `sin` 或 `cos`）可以用作资源名称，但有一个例外：例如，在等号右侧出现的 "`sin(1)`" 引用将被解释为对 `sin` 内置函数的调用，而不是名为 `sin` 的数组（Array）资源的第 1 个元素。其他内置函数同理。

资源类型名（如 "`Spacecraft`"）可以用作资源名称。在这种情况下，冲突由上下文解决。例如：

```
Create Spacecraft Spacecraft
Create Spacecraft aSat
```

在示例中，GMAT 通过上下文知道：在第二个 `Create` 语句中，参数 "`Spacecraft`" 指的是资源类型，而不是第一个语句创建的资源实例。

### 复合类型

#### 字面量数组

某些资源接受字面量数组作为输入。布尔值、整数和实数数组用方括号（"[" 和 "]"，十六进制：5B 和 5D）包围；字符串数组用花括号（"{" 和 "}"，十六进制：7B 和 7D）包围。在所有情况下，各值之间用空白字符或逗号分隔。只支持一维字面量数组。参见以下示例：

```
anOrbitView.DrawObject = [true true]             % boolean array
aSat.OrbitColor = [255 0 0]                      % integer array
anOrbitView.ViewPointVector = [3e4, 1.2, -14]    % real array
aSpacecraft.OrbitSpiceKernelName = ...
    {'file1.bsp', 'file2.bsp'}                   % string array
```

以上示例依次为：布尔数组、整数数组、实数数组，以及使用续行符书写的字符串数组。

#### 引用数组

某些资源接受对其他资源或资源字段的引用数组。这些引用数组用花括号（"{" 和 "}"，十六进制：7B 和 7D）包围，各值之间用空白字符或逗号分隔。只支持一维引用数组。各值可以选择性地用单引号包围。参见以下示例：

```
aForceModel.PointMasses = {'Luna', Mars}  % array of resource references
aReport.Add = {Sat1.X, 'Sat1.Y', Sat1.Z}  % array of parameter references
```

第一行是资源引用数组，第二行是参数引用数组；引号可选。

#### 类型转换

在接受实数的上下文中，整数字面量（即没有小数部分的值）会在执行时自动转换为等效的浮点值。

字符串值与数值之间没有内置转换，但个别命令可以自行实现此类转换。

#### 关键字

脚本语言识别以下保留关键字：

- `Create`
- `GMAT`
- `function`

此外，所有命令名都是保留的，包括由已激活插件创建的命令。
## 表达式

在多个命令之间通用的表达式只有逻辑表达式一种，它们被 `If`/`Else` 和 `While` 命令使用。因此将其记录在这里，而不是在两个命令的参考文档中分别记录。

### 关系运算符

逻辑表达式中支持以下关系运算符：

| 运算符 | 含义 |
|--------|------|
| `<` | 小于 |
| `<=` | 小于或等于 |
| `>` | 大于 |
| `>=` | 大于或等于 |
| `==` | 等于 |
| `~=` | 不等于 |

关系运算符是标量运算符；它们不作用于数组（Array）资源（只能作用于单个元素）。

每个关系运算符作用于其操作数的值，而不是它们的标识。考虑以下示例：

```
Create Variable x y
x = 5
y = 5

BeginMissionSequence

If x == y
    % body
EndIf
```

该示例中，`x` 与 `y` 的值相等（均为 5），因此 `x == y` 为真，循环体（此处为注释占位）将被执行。

### 逻辑运算符

逻辑表达式中支持以下逻辑运算符：

| 运算符 | 含义 |
|--------|------|
| `&` | 逻辑与（短路运算符） |
| `|` | 逻辑或 |

逻辑与运算符具有短路行为。也就是说，如果运算符左侧的求值结果为假，则不再对右侧求值，但右侧仍会被解析以检查语法有效性。

### 逻辑表达式

逻辑表达式由关系表达式通过逻辑运算符组合而成。

关系表达式必须包含一个关系运算符和两个合法的操作数。不支持字面量布尔值，数值也不会被解释为真或假。参见以下示例：

```
1 == 5          % false
1 ~= 5          % true
true            % error
1               % error
A               % where "A" is an Array resource; error
1 == 5 <= 3     % error
```

逐行说明：第 1 行 `1 == 5` 结果为假；第 2 行 `1 ~= 5` 结果为真；第 3 行单独的 `true` 是错误（不支持字面量布尔值作为关系表达式）；第 4 行单独的数值 `1` 是错误；第 5 行单独的数组资源引用是错误；第 6 行 `1 == 5 <= 3` 含有两个关系运算符，是错误（一个关系表达式只能含一个关系运算符）。

逻辑表达式必须至少包含一个关系表达式。多个关系表达式使用逻辑运算符组合。所有关系表达式先从左到右求值，然后整个逻辑表达式再从左到右求值，但短路与运算符（"`&`"）可能会提前终止整个求值过程。不允许使用括号。参见以下示例：

```
1 == 1                   % true
2 ~= 4 | 3 == 3          % true
8 >= 3 & 3 < 4           % true
2 < 4 & 1 > 3 | 5 == 5   % true
2 < 4 & (1 > 3 | 5 == 5) % error
1 & 1                    % error
true | false             % error
```

逐行说明：前四行均为合法的逻辑表达式且结果为真；第 5 行使用了括号，报错（不允许括号）；第 6 行 `1 & 1` 中操作数不是关系表达式，报错；第 7 行使用字面量布尔值，报错。

## 语句

### 语句结构

脚本语句按顺序由以下部分组成：

1. 可选的 "`GMAT `" 前缀
2. 合法的语句语法（可带可选的续行符）
3. 可选的分号
4. 行终止序列

脚本中的任何语句都可以加上 "`GMAT `" 前缀。该前缀是可选的且没有任何效果，仅为向后兼容而支持。

通过在语句内每个换行符之前使用续行标记——三个连续的句点字符（"`...`"，十六进制：2E2E2E），可以将一条语句拆分到多个物理行上。

任何语句都可以以分号字符（"`;`"，十六进制：3B）结尾。分号是可选的且没有任何效果，仅为向后兼容而支持。不能在一行上组合多条语句。

空白字符可以出现在语句的前后，或上述任何组成部分之间。一般也允许出现在语句内部的任何位置，例外情况会在相应语句的专门文档中注明。

### Create 语句

`Create` 语句是一种特殊语句，用于创建资源并为它们命名。它只在脚本的初始化部分中合法。它由以下部分组成：

1. `Create` 关键字
2. 资源类型
3. 资源名称（一个或多个）

`Create` 关键字表示语句的开始。其后是资源类型，指明要创建的资源类型。再往后是资源名称，即一个用户定义的名称，之后用该名称来引用这个特定的资源。该名称必须遵循前文列出的资源命名规则。

此语法的唯一例外是创建数组（Array）资源时，还必须指定资源的维数。

允许使用多个资源名称，此时将创建多个同类型的资源。多个名称之间用空白字符或逗号（"`,`"，十六进制：2C）分隔。

参见以下示例：

```
Create Spacecraft aSat  % creates a resource "aSat" of type Spacecraft
Create ForceModel aFM
Create Propagator aProp
Create Variable x y     % creates two Variable resources: "x" and "y"
Create String s1, s2    % creates two String resources: "s1" and "s2"
Create Array A[2,2]     % creates a 2x2 Array resource named "A"
```

逐行说明：第 1 行创建 Spacecraft 类型的资源 "aSat"；第 2、3 行分别创建 ForceModel 和 Propagator 资源；第 4 行一次创建两个变量资源 "x" 和 "y"（空格分隔）；第 5 行用逗号分隔创建两个字符串资源；第 6 行创建名为 "A" 的 2×2 数组资源（创建数组时必须指定维数）。

### 初始化语句

初始化语句是为资源字段赋初始值的特殊语句。它们只在脚本的初始化部分中合法，一般形式如下：

```
resource.field = value
```

某些字段（例如 ForceModel 资源上的字段）具有多重句点形式：

```
ForceModel.GravityField.PrimaryBody.Degree = value
```

所有初始化语句由以下元素组成：

1. 资源名称
2. 句点字符（"`.`"，十六进制：2E）
3. 字段名，可能是多重句点形式
4. 等号字符（"`=`"，十六进制：3D）
5. 字段初始值

资源名称必须引用同一脚本中先前已创建的资源。

字段名必须引用相关资源类型中存在的合法字段。不能用初始化语句设置参数（parameter），但设置双模式字段（即同时也可以作为参数的字段）是合法的。字段和参数在各资源类型的文档中列出。

所有值都按字面处理；不执行任何求值。因此，数值和字符串值必须以字面量形式指定，资源名称和参数则以引用形式存储。参见以下示例：

```
Create Spacecraft aSat
Create XYPlot aPlot
Create Variable x y z

x = 7100                   % valid
aSat.X = 7100              % valid
aSat.X = 7100 + 2          % error (mathematical expression)

aSat.X = x                 % error (field accepts literal, and variable
                           % evaluation does not occur)
aPlot.XVariable = x        % valid (field accepts reference to Variable x)
aPlot.YVariables = {y, z}  % valid (field accepts array of references to
                           % Variables y and z)
```

逐段说明：`x = 7100` 与 `aSat.X = 7100` 都是合法的字面量赋值；`aSat.X = 7100 + 2` 报错，因为初始化部分不允许数学表达式；`aSat.X = x` 报错，因为该字段只接受字面量且不会发生变量求值；`aPlot.XVariable = x` 合法，因为该字段接受对变量 x 的引用；`aPlot.YVariables = {y, z}` 合法，因为该字段接受对变量 y 和 z 的引用数组。

为了向后兼容，字面值规则有一个例外：`Spacecraft` 资源可以用如下初始化语句复制：

```
Create Spacecraft aSat1 aSat2
aSat2 = aSat1                   % Valid only for Spacecraft resources
```

即仅对 Spacecraft 资源，`aSat2 = aSat1` 这样的整体复制在初始化部分中是合法的。

在脚本初始化部分中没有赋值的字段，将保持各资源类型文档中规定的默认值。

### 命令语句

命令语句用于调用 GMAT 命令。它们必须出现在脚本的任务序列部分。有一个特殊命令 `BeginMissionSequence` 用于启动任务序列。

命令语句在 GUI 中显示为任务树中的单独行项。唯一的例外是 `BeginScript`/`EndScript` 复合命令，它在 GUI 中显示为单个 `ScriptEvent` 项。

命令语句由以下元素组成：

1. 命令名（赋值命令除外）
2. 可选标签
3. 命令参数

命令名是被调用命令的名称（例如 `Propagate` 或 `BeginFiniteBurn`）。命令名是必需的，但有一个例外：赋值命令通过其结构（"`LHS = RHS`"）而不是名称来标识。

命令标签是一个可选的字符串字面量，可以紧跟在命令名之后添加。GUI 使用该标签在任务树中为语句"命名"，用于帮助用户的简短文本说明。无论是否包含空格，它都必须加单引号。命令标签可以包含除某些不可打印字符（NUL、SUB）、行终止字符（LF、CR）、百分号（"`%`"）和单引号（"`'`"）之外的任何 ASCII 字符。如果省略命令标签，任务树中的语句将被赋予由命令名和 ID 编号组成的默认标签。例如，如果脚本中的第三个 `Propagate` 命令没有标签，它将被赋予默认标签 "`Propagate3`"。

命令参数控制命令的行为。参数的语法由各命令单独规定，并单独成文。有些命令（如 `Stop`）没有参数。

参见以下示例：

```
Propagate 'Prop to periapsis' aProp(aSat) {aSat.Periapsis}
```

在示例中，"`Propagate`" 是命令名，"`'Prop to periapsis'`" 是命令标签，"`aProp(aSat) {aSat.Periapsis}`" 是参数串。

### 复合语句

复合语句是控制其他命令语句执行的命令语句。复合语句由三个元素组成：

1. 开始语句
2. 主体
3. 结束语句

开始语句携带命令本身的名称，而结束语句以字符串 "End" 开头。例如，`While` 命令是由两条语句组成的复合命令：

```
While ['label'] arguments
    [body]
EndWhile
```

`If`/`Else` 复合命令由三条语句组成：

```
If ['label'] arguments
    [body]
Else
    [body]
EndIf
```

复合命令的主体可以由独立的命令语句组成，其中可能包括其他复合语句。某些复合命令可能会限制主体中可以出现的命令，而另一些命令可能只能包含在特定的复合命令中。这些限制在各命令的文档中单独说明。

## 处理过程

GMAT 分两个阶段处理脚本：解释（interpretation）阶段和执行（execution）阶段。本节概述处理顺序；底层细节记录在《GMAT 体系结构规范》第 17 章中。

### 解释阶段

GMAT 分两个步骤解释脚本：解析（parsing）步骤和验证（validation）步骤。在解析步骤中，GMAT 按顺序读取并解释脚本的每一行。在解释某一行时，GMAT 会检查其语法正确性，并执行该行所需的任何初始化。例如，如果被解释的行是 `Create` 语句，则创建相关资源；如果 GMAT 遇到初始化行，则将相应的值赋给指定的资源字段；如果遇到命令语句，则创建命令结构并解释其参数。所有语言、资源初始化和命令语法错误都在此解析步骤中被捕获。

在验证步骤中，GMAT 检查资源之间的所有引用是否有效。例如，如果脚本指示某个 `Spacecraft` 资源应相对于特定的 `CoordinateSystem` 资源定义，则该引用在此步骤中被验证。验证会检查所有被引用的资源是否存在且类型正确。

这种两步解释方法会影响脚本中语句的顺序。例如，`Create` 语句必须出现在脚本中引用所创建资源的任何初始化语句之前。但由于验证是单独执行的，`CoordinateSystem` 资源的 `Create` 语句可以出现在脚本中引用该资源的初始化行之后。参见以下示例：

```
Create Spacecraft aSat

% This is valid; the aSat resource has been created by the line above.
aSat.DateFormat = TAIGregorian

% This is invalid; the aReport resource has not yet been created.
aReport.Filename = 'report.txt'
Create ReportFile aReport
```

说明：`aSat.DateFormat = TAIGregorian` 合法，因为 aSat 已由上一行创建；而 `aReport.Filename = ...` 非法，因为 aReport 资源尚未创建（其 Create 语句在赋值之后）。

```
Create XYPlot aPlot

% This is valid; the reference to aSat is validated
% after all resources are created.
aPlot.XVariable = aSat.A1ModJulian

Create Spacecraft aSat
```

说明：本例合法。虽然 `aSat` 的 Create 语句在引用它的初始化行之后，但对 aSat 的引用是在所有资源创建完毕后的验证阶段检查的。

两个步骤都完成后，脚本就被加载到 GMAT 中。在 GUI（如果有）中，资源树将填充脚本初始化部分中创建的资源，任务树将填充任务序列中的命令语句。

解释阶段有时也被称为"构建（build）"阶段或"加载（load）"阶段。

### 执行阶段

任务运行时，GMAT 首先构建资源之间的相互连接，然后执行命令。在此阶段，任务序列中的所有命令按照脚本中定义的顺序依次执行。当一条命令语句被执行时，其参数由该命令完整处理，并报告任何剩余的错误。执行阶段错误的例子包括：数据类型不匹配、数组引用越界以及除零错误。

### 处理错误

如果 GMAT 在解释阶段（解析或验证）遇到错误，任务将不会被加载。此时 GMAT 会回退到仅包含以下内容的最小任务：

- `SolarSystem`
- 默认 `CoordinateSystem` 资源：`EarthMJ2000Eq`、`EarthMJ2000Ec`、`EarthFixed`、`EarthICRF`

如果在执行阶段（连接或命令执行）遇到错误，任务的执行将在出错点停止。
