# 仿真 GPS_PosVec 测量（Simulate GPS_PosVec measurements）
> 译自 GMAT R2026a 帮助文档 ch15s02.html

我们首先创建对象并配置一个 GMAT 脚本来仿真星载 GPS 位置测量。当然，在实际中你不会为了轨道确定（OD）而运行仿真器，你会使用来自卫星遥测的实际测量数据。

首先打开 GMAT。

1. 找到你的 GMAT 安装目录，在 *<GMAT 安装目录>*/bin 目录中找到并双击 GMAT.exe 启动应用程序。

你可以关闭出现的欢迎窗口。接下来我们新建一个空白脚本文件。

2. 在 GMAT 的 File 菜单中，选择 New > Script（新建 > 脚本）。

一个脚本窗口将在 GMAT 图形界面中打开。本教程的其余部分都将在这个脚本窗口中工作。我们首先创建用于仿真测量的 Spacecraft（航天器）对象。

3. 在 GMAT 脚本窗口中输入或粘贴以下内容。

```
%
%   Spacecraft
%

Create Spacecraft SimSat;

SimSat.DateFormat        = UTCGregorian;
SimSat.Epoch             = '10 Jun 2014 00:00:00.000';
SimSat.CoordinateSystem  = EarthMJ2000Eq;
SimSat.DisplayStateType  = Cartesian;
SimSat.X                 = 576.869556
SimSat.Y                 = -5701.142761
SimSat.Z                 = -4170.593691
SimSat.VX                = -1.76450794
SimSat.VY                = 4.18128798
SimSat.VZ                = -5.96578986
SimSat.DryMass           = 10;
SimSat.Cd                = 2.2;
SimSat.Cr                = 1.8;
SimSat.DragArea          = 10;
SimSat.SRPArea           = 10;
SimSat.Id                = 'LEOSat';

%
%   Mission sequence
%

BeginMissionSequence
```

上述脚本创建名为 SimSat 的航天器，设置历元格式、历元、坐标系（EarthMJ2000Eq）、笛卡尔初始状态、干质量、阻力系数 Cd、光压系数 Cr、阻力面积、光压面积及标识符，最后以 BeginMissionSequence 开始任务序列。

4. 在脚本窗口底部，点击 "Save,Sync"（保存并同步）按钮。
5. GMAT 会询问你是否要保存脚本并将其设为活动脚本。点击 "Yes" 并选择一个目录保存脚本。我们把它命名为 "simulate.script"。
   a. 保存后，GMAT 控制台窗口应显示消息 "Successfully interpreted the script"（脚本解释成功）。

让我们花点时间理解脚本与图形界面之间的关系。首先，虽然 GMAT 有完善的图形界面，但大多数 GMAT OD 组件没有图形界面，只能通过脚本配置。一些 OD 资源（如 Spacecraft、GroundStation 和 ForceModel）确实有图形界面，可以通过图形界面或脚本创建和配置。"Sync"（同步）功能用于将脚本中的对象配置与图形界面资源树中的配置"同步"。当你点击 "Save,Sync" 或 "Save,Sync,Run" 按钮时，GMAT 会保存你的脚本更改，然后更新图形界面资源树中所有适用对象，以反映你在脚本中对它们所做的更改。你可以在执行 "Sync" 操作后双击资源树中的任何对象来验证这一点。如果你愿意，现在就可以对 SimSat 航天器这样做。所选对象的图形界面将显示脚本中的当前设置。你应看到图形界面中的初始状态和航天器参数与脚本中赋予的一致。图形界面的 Mission（任务）选项卡也是如此。我们尚未在任务序列中配置任何步骤，但一旦配置，它们将出现在图形界面的 Mission 选项卡下。然而，由于大部分轨道确定处理无法通过图形界面配置，在本教程的其余部分我们将忽略图形界面，只专注于使用脚本编辑器完成我们的 OD 任务。

> **注意**：在本教程中，避免使用 Control-S 或工具栏 "Save" 图标保存脚本。这些操作与 "Save/Sync" 按钮的方向"相反"。使用 Control-S 或 Save 图标会导致 GMAT 用自动生成的代码替换你的脚本文件——即把对象配置转储为脚本格式。虽然这绝不会影响脚本的功能，但通常会导致代码更冗长、更"难看"。执行此操作时，GMAT 会在与脚本相同的目录中生成原始脚本的 ".bak" 备份版本。如果你不小心这样做了，可以从 ".bak" 副本恢复原始脚本。

GMAT 脚本语言是"面向对象"的，这意味着系统中的每个组件都是一个自包含的对象（在 GMAT 中称为"资源"），带有一组需要指定以配置资源状态的参数。GMAT 有许多内置资源，用于对航天器任务规划的各个方面建模。这些资源的名称、描述和可用参数见用户指南的"Reference Guide（参考指南）"部分。要使用资源，用户必须创建资源的实例并按需配置。资源名称由 GMAT 固定，但实例名称可由用户在语法规则内选择。在上面的例子中，**Spacecraft** 是内置航天器资源类的名称，我们这里创建了航天器的一个实例并选择将其命名为 SimSat。然后用户使用他们创建的资源实例进行工作。由于这种范式与 Java 和 Python 等其他常见面向对象编程语言相似，希望你已经熟悉它。

在继续创建仿真脚本的其余部分之前，我们应花些时间进一步了解 GMAT 脚本文件的结构。总体而言，GMAT 脚本有两部分——对象配置部分和任务序列。在脚本的"对象配置"部分，我们创建并指定完成所需任务所需的全部 GMAT 资源（对象）的初始配置。"任务序列"定义使用已配置对象执行所需任务的步骤。它可以是传播航天器、target 机动，或者（在我们的例子中）仿真和估计轨道。对象配置必须始终在任务序列之前，两部分由 BeginMissionSequence 关键字分隔。任务序列中的代码步骤最终会填充到图形界面左侧栏的 "Mission" 选项卡中，但我们的 OD 任务不会与图形界面交互。现在，我们将先创建所需的全部对象，稍后再填写任务序列。

在我们进入任务序列部分的练习之前，下面指示你粘贴到脚本中的所有内容都应插入到 BeginMissionSequence 行之前。

让我们继续构建脚本以仿真 GPS 位置测量数据。接下来要做的是为航天器创建一个 GPS 接收机。在 GMAT 中，GPS 接收机对象负责 GPS 测量数据的建模。

6. 在 GMAT 脚本窗口中输入或粘贴以下内容。

```
%
%   Spacecraft hardware
%

Create Antenna GpsAntenna;
Create Receiver GpsReceiver;

GpsReceiver.PrimaryAntenna = GpsAntenna;
GpsReceiver.Id             = 800;
GpsReceiver.ErrorModels    = {PosVecModel}

Create ErrorModel PosVecModel;
 
PosVecModel.Type       = 'GPS_PosVec'
PosVecModel.NoiseSigma = 0.010;
```

上述脚本创建三个新对象：Antenna（天线）GpsAntenna、Receiver（接收机）GpsReceiver 和 ErrorModel（误差模型）PosVecModel；接收机关联天线、设置 Id 为 800、挂载误差模型；误差模型类型为 GPS_PosVec，噪声 sigma 为 0.010 km。

7. 在脚本窗口底部，点击 "Save,Sync" 按钮。

这里我们创建了三个新对象——一个 Antenna、一个 Receiver 和一个 ErrorModel。我们的 GpsReceiver 对象连接到一个 Antenna，并拥有一个 Id 和一个 ErrorModel。Antenna 用于确定 GPS 测量的信号路径，除此之外没有其他功能。Receiver Id 是接收机的唯一标识符。仿真 GPS 数据时，你可以为它选择任何值，它将应用于仿真数据；但使用实际的 GPS 航天器测量记录时，此 Id 必须与格式化 GMAT 输入 GPS 记录上的 Id 匹配。GMAT 输入数据记录的格式稍后会详细描述。

最后，我们创建了一个 ErrorModel 并将其挂接到 Receiver。GMAT ErrorModel 是一个通用对象，描述用于 OD 的测量的属性。由于 ErrorModel 是通用的，我们首先要指定为它配置 GMAT 的哪种测量类型，本例中为 GPS_PosVec 测量类型。GPS_PosVec 是指定 GPS 测量数据时必须使用的内置名称。其他测量类型有类似的内置名称。更多细节请参阅"Tracking Data Types for Orbit Determination（轨道确定的跟踪数据类型）"。

接下来，我们指定与 GPS 测量数据相关的测量噪声。NoiseSigma 表示测量数据的 1-sigma 噪声。由于我们正在搭建仿真脚本，这表示将添加到仿真测量中的噪声。当我们进入估计步骤时，此 NoiseSigma 将被解释为假定存在于测量中的测量噪声。GMAT 中每种测量类型的 NoiseSigma 单位不同。对于 GPS_PosVec 测量，单位是千米，因此这里我们指定的 1-sigma 测量噪声为 10 米。处理真实航天器 GPS 测量数据时，通常需要一些分析来确定合适的噪声值。

注意，我们把 ErrorModel 的实例（PosVecModel）挂接到 GPS 接收机，而不是 ErrorModel 本身。同样，这符合常见的面向对象编程范式。现在我们还必须把创建的接收机挂接到航天器上。

8. 在脚本中，回到航天器参数配置部分，在航天器参数列表底部添加以下内容。

```
SimSat.AddHardware       = {GpsReceiver, GpsAntenna};
```

上述脚本把接收机和天线（以及隐含地挂接的接收机 GPS 测量误差模型）挂接到航天器。

9. 在脚本窗口底部，点击 "Save,Sync" 按钮。

虽然不是严格必要，但把所有航天器参数放在一起很方便。这里我们把接收机和天线（以及隐含的接收机 GPS 测量误差模型）挂接到航天器，供运行仿真时使用。

我们的目标是仿真一些 GPS 测量数据，供后续估计运行使用。GMAT 通过 TrackingFileSet（跟踪文件集）资源处理测量数据。

10. 在 GMAT 脚本窗口中输入或粘贴以下内容。

```
%
%   Tracking file sets
%

Create TrackingFileSet SimData;

SimData.AddTrackingConfig = {{SimSat.GpsReceiver}, 'GPS_PosVec'};
SimData.FileName          = {'gps_posvec.gmd'};
```

上述脚本创建跟踪文件集 SimData，AddTrackingConfig 指定测量路径（SimSat.GpsReceiver）和测量类型 GPS_PosVec，FileName 指定输出文件 gps_posvec.gmd。

11. 在脚本窗口底部，点击 "Save,Sync" 按钮。

这里我们创建了跟踪文件集的一个实例，它将写出仿真测量数据。对于 GPS_PosVec 测量数据，我们只需指定两件事——仿真数据的跟踪配置（即测量路径），以及将包含仿真测量的输出文件名。AddTrackingConfig 参数的内层花括号指定仿真数据的测量路径。GPS_PosVec 数据虽然实际上由测量航天器相对于多颗 GPS 卫星的位置导出，但只包含航天器状态的 X、Y、Z 估计，因此我们的仿真用例只需指定仿真中使用哪个 GPS 接收机。回想一下，挂接到该接收机的 ErrorModel 将提供仿真中施加的测量噪声。在内层花括号之外，我们指定要仿真的测量数据为 GPS_PosVec 测量类型。其他测量类型通常有更复杂的测量路径，需要跟踪文件集的更多参数。你可以参考用户指南中的示例。

跟踪文件集的 FileName 指定仿真测量的输出文件。这里我们只指定文件名（不含完整路径）。在这种情况下，GMAT 默认会把文件写入 *<GMAT 安装目录>*/output 目录。如果你想把文件写到其他目录，请指定文件的完整路径。

顺便说一句，如果点击 "Save,Sync" 后你看到提示语法或脚本错误的消息，请停下来检查你的工作。我们逐步添加的所有代码都应始终能成功解析。

接下来我们需要创建用于此轨道仿真的力模型。

12. 在 GMAT 脚本窗口中输入或粘贴以下内容。

```
%
%   Force model
%

Create ForceModel FM;

FM.CentralBody                       = Earth;
FM.PrimaryBodies                     = {Earth};
FM.GravityField.Earth.Degree         = 8;
FM.GravityField.Earth.Order          = 8;
FM.GravityField.Earth.PotentialFile  = 'JGM2.cof';
FM.SRP                               = On;
FM.Drag.AtmosphereModel              = 'JacchiaRoberts';
FM.Drag.CSSISpaceWeatherFile         = 'SpaceWeather-All-v1.2.txt'
FM.Drag.HistoricWeatherSource        = 'CSSISpaceWeatherFile';
FM.ErrorControl                      = None;
```

上述脚本创建力模型 FM：中心天体地球，8×8 JGM2 重力场，开启光压，使用 JacchiaRoberts 大气模型与 CSSI 空间天气文件，ErrorControl 设为 None（定步长积分）。

13. 在脚本窗口底部，点击 "Save,Sync" 按钮。

FM 是 ForceModel 的一个实例，包含地球 8x8 重力建模、使用 Jacchia-Roberts 大气密度模型的大气阻力以及太阳光压。我们配置力模型使用 CSSI 格式的空间天气文件进行大气密度建模。该文件包含每日太阳通量和每 3 小时的行星地磁指数。在本例中，由于未指定完整路径，我们将直接使用该文件的默认副本，位于 *<GMAT 安装目录>*/data/atmosphere/earth 目录。如果你想使用该文件的不同版本，可以指定完整路径。对于受阻力影响的低地球卫星的轨道确定，使用每日更新版本的此文件是最佳实践。

值得一提的是，设置 `FM.ErrorControl = None` 强制 GMAT 在传播轨道时使用定步长积分。目前使用 GMAT 进行轨道确定时必须如此。

快完成了，只需再创建几个对象。现在配置传播器。

14. 在 GMAT 脚本窗口中输入或粘贴以下内容。

```
%
%   Propagator
%

Create Propagator Prop;

Prop.FM              = FM;
Prop.Type            = 'RungeKutta89';
Prop.InitialStepSize = 60;
Prop.MinStep         = 0;
Prop.MaxStep         = 60;
```

上述脚本创建传播器 Prop：关联力模型 FM，类型 RungeKutta89，初始步长 60 s，最小步长 0，最大步长 60 s（即定步长 60 s）。

15. 在脚本窗口底部，点击 "Save,Sync" 按钮。

我们的 ForceModel 实例 FM 被指定给传播器使用。由于在力模型上我们为轨道指定了定步长积分（`FM.ErrorControl = None`），在传播器上我们必须指定积分步长。这里我们使用 60 秒步长，这对低地球轨道卫星很典型。我们还使用了高阶数值积分器（RungeKutta89 传播器），这使得使用 60 秒步长更安全。合适的步长会随任务轨道类型、积分器选择和力建模而变化。注意，要配置 60 秒固定积分步长，必须在 InitialStepSize 和 MaxStep 参数上都指定 60 秒，同时将 MinStep 设为零。

现在快完成了！还需配置一个对象，然后我们将进入运行仿真所需的任务序列。在此之前，我们最后要创建 Simulator（测量仿真器）资源。

16. 在 GMAT 脚本窗口中输入或粘贴以下内容。

```
%
%    Simulator
%

Create Simulator Sim;

Sim.AddData              = {SimData};
Sim.EpochFormat          = 'UTCGregorian';
Sim.InitialEpoch         = '10 Jun 2014 00:00:00.000';
Sim.FinalEpoch           = '11 Jun 2014 00:00:00.000'; 
Sim.MeasurementTimeStep  = 600;
Sim.Propagator           = Prop;
Sim.AddNoise             = On;
```

上述脚本创建仿真器 Sim：AddData 关联跟踪文件集 SimData，起止历元 2014-06-10 至 2014-06-11（UTCGregorian），测量时间步长 600 s，使用传播器 Prop，AddNoise 开启（添加噪声）。

17. 在脚本窗口底部，点击 "Save,Sync" 按钮。

仿真器对象将使用我们迄今配置的所有对象执行测量仿真。在 AddData 参数上，我们指定跟踪文件集，它指定了数据仿真的测量路径。这把仿真器链接到航天器、GPS 接收机、测量模型以及仿真测量的输出文件。仿真器还指定数据仿真跨度的开始（InitialEpoch）和结束（FinalEpoch）时间，以及仿真观测记录的间隔（MeasurementTimeStep）。由于仿真器负责在仿真跨度内传播航天器，我们也将传播器（及其挂载的力模型）指定给仿真器。最后，我们可以选择是否向仿真测量添加噪声。如果 AddNoise 设为 Off，航天器 GPS 接收机误差模型上指定的噪声 sigma 将被忽略，仿真测量将是"完美"的。

现在我们已拥有正确配置仿真所需的全部资源，几乎准备好执行仿真了。现在该构建使用已创建对象执行仿真的任务序列了。在本例中，只需要一行代码。

18. 按下面所示更新任务序列，然后点击 "Save,Sync"。

```
%
%   Mission sequence
%

BeginMissionSequence

RunSimulator Sim;
```

RunSimulator 命令有一个参数——要执行的仿真器实例名称。该命令指示 GMAT 使用挂载到仿真器及其关联对象的测量链、传播器、航天器和误差模型生成仿真测量。

仿真脚本的构建到此为止——现在终于可以运行它了。

19. 在脚本窗口底部，点击 "Save,Sync,Run" 按钮。或者，你可以点击工具栏中的蓝色 "Run" 箭头，或按 F5 键来执行 GMAT 脚本。

脚本运行很快——应在几秒内完成。在控制台窗口（脚本编辑器正下方的文本输出区）中，应出现消息 "Mission run completed"（任务运行完成）。你还会看到一条警告："The orbit state transition matrix does not currently contain SRP contributions from shadow partial derivatives when using Spherical SRP"（使用球形 SRP 时，轨道状态转移矩阵当前不包含阴影偏导数的 SRP 贡献）。此消息在使用 SRP 建模时属正常，提醒用户 GMAT 忽略了 SRP 计算中的一个小的修正，本练习中我们无需担心。

运行的唯一其他输出是仿真测量文件。回想一下，在跟踪文件集上我们把 'gps_posvec.gmd' 设为仿真数据文件名。由于未指定完整路径，GMAT 已在其默认位置 *<GMAT 安装目录>*/output 目录中创建了此文件。查看你的输出目录，找到新文件。

在文本编辑器中打开 gps_posvec.gmd 文件。你会看到类似以下内容。由于我们配置仿真器向测量添加随机噪声，你文件中的数据会与这些值略有不同。

```
% GMAT Internal Measurement Data File

26818.5004050925930316268847    GPS_PosVec    9014    800    5.4582066502576909e+03    1.7472147130503795e+03    -4.1695115857105557e+03
26818.5073495370382845110637    GPS_PosVec    9014    800    2.3029538831047935e+03    -1.4045595913124220e+02    -6.7023373462614209e+03
26818.5142939814798994164372    GPS_PosVec    9014    800    -1.8916402292545524e+03    -1.6523319919249177e+03    -6.6283229876018404e+03
26818.5212384259251523006163    GPS_PosVec    9014    800    -5.4440068853410785e+03    -2.1862351512631685e+03    -3.9759522335154807e+03

```

这是一个 GMAT 测量数据（即 GMD）文件的示例。GMAT 处理的所有测量类型的文件格式都非常相似，由一系列按时间排序的 ASCII 记录组成，数据字段以空格分隔。"Tracking Data Types for Orbit Determination（轨道确定的跟踪数据类型）"中描述了所有受支持测量类型的此格式。为方便起见，下面转载 GPS_PosVec 数据的格式。

| 字段 | 描述 |
|------|------|
| 1 | 观测时刻的 TAI 修正儒略日 |
| 2 | 观测类型名称——GPS_PosVec |
| 3 | 观测类型索引号（GPS_PosVec 数据为 9014） |
| 4 | GPS 接收机 ID |
| 5 | 地球固连位置 X 分量（km） |
| 6 | 地球固连位置 Y 分量（km） |
| 7 | 地球固连位置 Z 分量（km） |

注意，仿真记录中的接收机 ID 与我们在脚本中为 GpsReceiver 对象指定的 Id 匹配。所示的 X、Y、Z 分量就是航天器在地球固连参考架中的预测（传播）X、Y、Z 位置，并添加了 10 米随机噪声（如 PosVecModel 误差模型所指定）。这就完成了仿真星载 GPS 位置估计的任务。

在下一节中，我们将继续创建一个使用这些数据估计航天器轨道的脚本。
