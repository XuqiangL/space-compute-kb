# GMAT 架构解析文档 · 撰写规范（所有子代理必读）

本目录 `L:\gmat888\gmat-architecture-docs\` 是最终交付的中文分章节 Markdown 文档集合。
仓库根目录是 `L:\gmat888`（depth-1 克隆，无法查 git 历史，不要尝试）。

## 一、语言与格式
- 正文用简体中文；类名、函数名、文件名、代码标识符保留英文原样。
- 每章一个文件：`CH<两位数编号>-<英文slug>.md`，如 `CH02-foundation.md`。
- Markdown 标题层级：`#` 章标题 → `##` 大节 → `###` 目录/模块 → `####` 单个文件/类。
- 目录树用代码块内的 ASCII 树；不要求 Mermaid。

## 二、每章固定结构
1. `# 第X章 <标题>`，紧接着一行本章范围说明（负责哪些目录、共多少文件）。
2. `## 一、本章目录树`：ASCII 树（含文件数）。
3. `## 二、逐文件/逐类讲解`：按目录分组，逐文件讲解（格式见下）。
4. `## 三、关键设计模式与数据流`：本章范围内的继承体系、工厂模式、数据流、调用链。
5. `## 四、文件清单附录`：一张表 `| 相对路径 | 职责 | 关键类/函数 |`，覆盖本章全部代码文件（大目录可多张表）。

## 三、逐文件讲解格式
对每个源码文件（.hpp/.cpp）给出：
- 职责一句话；
- 关键类/函数列表（含 2~8 句中文注释式解读，讲清"干什么、为什么这么写"）；
- 重点类展开：构造、关键虚函数（如 GmatBase 的 Initialize/Execute/Copy/Clone/GetParameter）、继承关系、参数表、单元换算等细节；
- 引用代码时标注真实相对路径与行号（必须先 read 确认），代码片段用 ```cpp 围栏，片段控制在 5~30 行，片段后附中文逐行解释。
- 禁止整文件粘贴；禁止编造行号与不存在的符号。

## 四、覆盖标准
- 所有 `.hpp/.cpp/.c/.java` 代码文件必须逐文件覆盖（重点文件详细讲，一般文件 2~6 句）。
- `.txt/.script/.json/.xml/.ini/.cfg/.html/.pdf` 等数据/文档类文件按"目录级说明 + 代表性文件深读 + 表格清单"覆盖。
- 二进制文件（.exe/.dll/.png 等）只列表说明用途，不分析。

## 五、工具与纪律
- 用 glob（不要 shell find）发现文件，用 grep 搜索内容，用 read 读文件；可用 pwsh 做目录列举与计数，但不要用 shell cat 读源码。
- 只允许写入自己负责的章节文件；严禁修改仓库源码、严禁写别人的章节。
- 每个写进文档的路径必须真实存在（先用 glob 验证）。
- 章节之间交叉引用用相对链接，如 `[第3章](CH03-math-util.md)`。

## 六、质量底线
- 不要水字数：删除空话、重复段落；每条讲解都要有信息量。
- 章节目标篇幅：核心章（base/gui/plugins 各章）6,000~15,000 行左右由内容自然决定，以"讲清"为准，不以凑长为目标。
- 结尾不要写"本章小结/感谢阅读"之类的套话，用`四、文件清单附录`收尾即可。
